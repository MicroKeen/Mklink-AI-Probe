## 首轮结果与修复

- 初始安装包 `5bdd1611` 和 Skill `cafe835f` 产品代码相同。全套软件回归为
  Python 6383 通过、2 失败、2 跳过；GUI 1164 通过、1 失败。三个失败均为旧测试
  假设备/提示文本假设，修正后整文件重跑 10 Python、124 GUI 通过。
- V2 / STM32H743：14 个声明 SWD 档位均确认应用并读出 CPUID；10/30 MHz 下
  4–4096 字节 RAM 读取、480 字节写回恢复、多区域 flush 通过。内置 AXF/DWARF、
  变量、健康 HardFault 基线、halt/step/resume、FPBv2 两个半字断点命中和清除通过。
- 冻结 MCP 56 工具通过共享后台接入；无供电确认时拒绝写入，不改用独占 CDC。
  V2 当前没有 get_memory、可编程供电/功耗查询、蜂鸣、auto_scan、auto_follow_vref；
  宿主现按缓存版本在命令发送前明确提示型号固件不支持，不声称升级即可解决。
- RTT 下行 256 字节目标计数/滚动哈希一致；上行 172032 字节逐序号、逐字节核对通过，
  未发生订阅丢失。RTT、1 ms SuperWatch、SystemView 可并行推进。
- 原工程 BIN 223048 字节与 HEX 一致，SHA-256 为
  `54f1a44320a9b865d6e8743cd18b3d34bd356bf217735a575453a0598f11d039`。
  SDK 烧录实际使用 DAPLink 内置算法/`load.bin`，不能当作 GUI pyOCD 在线链路证明。
- 首轮下载成功后，RTT/SystemView 在目标初始化控制块前启动失败，而任务回执错误地
  报告已恢复。现仅在下载恢复阶段有限等待目标 RAM 内有效的控制块及所选通道，
  然后执行一次启动，并等待真实工作线程启动确认。传输错误直接失败，不重放启动/下载。
  源码实机复测：烧录与全镜像回读通过，三个采集自动恢复，SystemView 新增事件且无丢失计数。
- 首轮脱机部署时仍保留空闲 MUX，后续退出 MUX 等待心跳超时，任务保留 unknown 且未重发。
  固件会话确认 V2 在 MUX 活跃时不处理 MSC 写入；该错误不能证明离线命令已经发送。
  现文件部署和单独 FLM 拷贝均先正常退出 MUX，再执行现有 fsync/SHA 核验复制。
  新请求实机通过真实 MSC 写入、单次 `load.offline()`、完成标记与全镜像回读。
- 源码复测早期读取到一条历史 SystemView overflow 记录，保留原证据；不宣称整段运行零溢出。
  后续烧录复位后重新采集的 overflow/parser/transport 计数为零。

相关修复回归 291 项通过；补充 SystemView 下行描述符就绪测试后，仍需完整软件回归、
生产构建、新 Windows/Skill 覆盖安装及 GUI 在线链路验收。V2 此时尚不能宣告整体验收完成。
