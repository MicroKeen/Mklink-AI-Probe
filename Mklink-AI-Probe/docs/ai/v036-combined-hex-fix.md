# 0.3.6 内外 Flash 合并 HEX 修复

## 问题与修复

客户在 N32WB452xE 在线烧录中选择内置 Flash 算法和用户添加的 SPI Flash 算法，合并 HEX 的两段地址均已识别，但出现“当前 FLM 未提供可验证的完整扇区布局”，无法开始烧录。

两份 FLM 本身均包含有效几何。`CustomFlmCatalog` 已解析并保存页大小与扇区表，但 `algorithm_catalog._custom_algorithms()` 构造统一算法记录时遗漏 `page_size`、`sector_sizes`。显式组合选择使用统一记录，因此丢失自定义算法几何，触发扇区操作拒绝。

产品提交 `6c2095c7` 补齐这两个字段，继续使用既有范围、重叠、摘要和扇区校验；不放宽未知几何的限制。集成安装源 `f4221d96` 同时包含在线进度/重复擦除修复 `8063140b`（功能源 `35f7da59`），保留先前 RTT/SuperWatch 修复。

0.3.6 中英文版本信息增加两条简短说明：修复内外 Flash 合并 HEX 的组合烧录；修复在线烧录进度到 100% 后等待过久的问题。

## 验证

- 回归测试使用真实 CustomFlmCatalog 落盘、重新加载和算法发现，不再只模拟已经带有扇区表的算法。覆盖不同页大小、分段扇区布局、合并 HEX 检查、任务准入和最终算法资产。
- 388 项相关 Python 测试及 5 项版本信息组件测试通过，`git diff --check` 通过。
- 客户文件只用于本地验证，未提交仓库。SPI FLM：基址 0、容量 4 MiB、4 KiB 页/扇区；内部 FLM：基址 0x08000000、容量 512 KiB、2 KiB 页/扇区。
- 客户 HEX 包含 `[0, 0x00400000)` 和 `[0x08000000, 0x080011EC)` 两段。两份自定义算法，以及内置内部算法加自定义 SPI 算法，均得到 1,027 个覆盖扇区（1,024 外部、3 内部），验证消息为空；模拟任务管理器接受正确区域及算法资产。
- 实际生产 Web 页面配合隔离的真实解析 API，在浏览器选择内置内部算法与自定义 SPI 算法并上传客户 HEX 后，显示 FLM 已验证、扇区列表和可用的“开始烧录”，无布局报错。未操作实体探针。
- 标准无签名 NSIS 构建成功，包源 `f4221d96`，生产 Web 归档提交 `d7d2db3d`。安装包 SHA-256：`82f95c6310507fbe832b6749f3752e26be7af07384034f0f66ab80765e404cf7`。
- 管理员覆盖安装退出码 0。解包与安装后的冻结资格检查均通过：206 个 Python 源文件、41 个 Web 资源与构建输入一致，安装载荷与解包载荷一致；Windows-only PATH 下 CLI/MCP/SVD/HTTP、探针枚举、无宿主 Python、后台正常退出均通过。
- 客户两份真实 FLM 和合并 HEX 再经解包与安装后的冻结 API 导入、解析，均得到 1,027 个有效扇区；未创建实体烧写任务。
- 安装后的原生程序启动、健康状态正常；实际浏览器加载其生产仪表盘与版本弹层，核对两条新修复说明，控制台无错误。原生窗口留给用户，未连接或烧写 MCU。本次无需下载器固件修改。

## 边界

本次定位并修复的是算法几何丢失造成的主机准入失败。没有 N32WB452 实物烧写/回读证据；模拟任务通过和真实文件解析通过不能替代外置 SPI Flash 的客户硬件测试。前一个 STM32F103 进度修复的单次实体重烧及完整回读已通过，授权已消耗，不重复烧写。
