## 优先处理的正确性问题

1. **下载成功与校验成功不能混同。** 固件 `external/pikapython/pikascript-lib/riscv_hpm/py_riscv_hpm.c` 的 `program_bin_flash` 目前检查编程返回，没有独立 Flash 回读；内存分配失败路径还存在返回 NULL（数值0，被视为成功）的风险。草稿仅检查 `hpm.program()!=0`。必须先审查并修复失败返回、确认校验策略，再允许其作为不可逆 OTP 执行门槛。此前对用户提到的“下载并校验成功”尚未实现为此脱机链路的保证。
2. 审查旧探针缺少 OTP API 时是否在任何擦写之前明确停止；识别 V4 不等于确认 HPMLink 固件能力。预检异常和 Pika 解释器行为必须验证。
3. 执行生成脚本的故障注入测试：首个/第二个文件失败、预检失败、首个 OTP 失败、锁失败均停止；数据写完才锁；多个锁预期值正确；禁止清位、错误型号、空配方、重复 Word/组及缺少确认。
4. GUI：确认撤销、切换型号、重新生成预览、API错误显示、默认关闭；补英文文案及组件测试，再用真实 Chrome 核对生成脚本。审查预览/部署入口是否一致传递新字段。
5. 中途失败可能已经写入部分 OTP，必须回读后重建配方，不得自动重试原配方。多轮量产每颗芯片都重新核对旧值；不要为了重复烧录绕过旧值保护。
