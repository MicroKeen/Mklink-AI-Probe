## 定位

已选变量描述符原来调用模糊搜索。`GPIOE.IDR.ID2` 中的数字触发
`SymbolCatalog._search_lazy` 的宽泛数字判断，导致展开不匹配的大数组；
搜索直接运行在 HTTP/WebSocket 事件循环。真实 H743 符号表下每次约
1.75–1.87 秒，能重现 Watch 接收队列删除及毫秒级时间戳缺口。

现改用精确路径解析已选项；模糊搜索仅对数组下标/独立数字词保留索引匹配，
并移到线程池。相同搜索请求降为 35–72 ms。未扩大缓冲或改变目标固件。

无界面基线八组最大间隔 46–66 µs。搜索负载下明确发生 MUX 队列删除；
诊断快照中父进程 inbox 峰值约 25–28 KiB，未接近 1 MiB 上限。
未直接测量每次 USB 完成和 worker 队列峰值，**USB 背压尚未证实或排除**。
127 点边界对齐也可来自主机整批删除，不能独立证明探针暂停；新对照不作为
此前七处缺口的唯一归因。原失败证据保留。

## 同负载 40/100 µs 对照

普通 V4、同一 USB7 固件/H743 映像、SWD 30 MHz。单变量 4 字节、请求间隔
4 µs、界面缓冲 50000 点、产品 JSONL 关闭；真实 Chrome 程序变量面板打开。
每次开始后 0.75 秒发一次相同的 GPIO 符号搜索，每组两次；名义采集 3 秒，
阻塞可能延长实际时长。独立鉴权二进制订阅者保存所有已发布帧，停止后落盘。
速率按设备首末时间戳计算，不按宿主接收速度。

## Hz 与缺失语义

- Hz 改为设备时间戳和成功样本数的约一秒窗口，保留真实采集停顿；无设备
  时间戳时不伪造速率。旧 UI 在积压排空时显示过 16–30 万 Hz，新 UI 与设备
  统计约 14.25/23.70 万一致。
- 删除“视窗最大间隔/空隙 >20 µs”显示。时间差本身不判丢点、不置灰。
- 队列丢弃、明确读失败、无法组成完整样本的分片，按顺序标在下一有效点前，
  断线并置灰。原值和时间戳不变，无法恢复缺失电平。
- MUX 全局序号涵盖 Watch/RTT/状态，缺号无法确定内容，只断线、不置灰。
  不按缺号乘 127，也不根据时间差计算丢点数。
- WebSocket 独立样本序号识别本订阅者缺失；丢元数据帧或其他客户端丢弃不会
  误判本曲线丢点。边界保留到冻结/缩放/回放。

`/ws/streams/superwatch?continuity=1` 协商 flag 4：小端 `<QII>` 首样本序号、
边界数、保留零；随后原 flag 3 时间戳/数值，再附每个 `<II>` 批内索引/原因。
原因 bit 0 明确缺失，bit 1 不明连续性。未协商仍发原 flag 3，新 Worker 仍
读旧布局。JSONL 在有效点前写独立 `event=discontinuity, reason=1..3` 元数据，
不覆盖合法目标变量名。
