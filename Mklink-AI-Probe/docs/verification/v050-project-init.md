# 通用工程配置与可选初始化

2026-11-10，在 `codex/v0.5.0-fixes` 的 `84006d7e` 基础上修复。
触发场景是普通 STM32 CMake/CLion 工程无法导入，烧录缺少型号时又被引导去执行
`project-init`。本轮修改工程输入与提示，不修改烧录协议、算法选择规则或固件。

## 行为

- `project-init` 保留为可选离线工具。显式 `--target-part` 可以配置任意工程目录，
  `--firmware`/`--hex` 保存 HEX/BIN 路径，`--elf`/`--axf` 保存 ELF/AXF/OUT 路径。
- 初始化的相对路径以项目根目录为准并保存为绝对路径；允许编译前配置产物。
  原有连接、RTT 和工具链设置保留。无显式型号时继续支持 Keil/IAR/HPM 导入。
- 普通 CMake 的 bin/elf/map 输出组合不再单独作为 HPM SDK 的识别依据。
- 未知工程缺型号、非法输入、损坏配置返回非零退出码；API 的 `success` 与结果一致。
- 已存型号与新输入不同，或存在旧 `mcu_key` 时，显式初始化拒绝覆盖并说明原因。
  不自动迁移芯片相关配置，避免 HPM 参数或旧 FLM 影响新目标。
- 直接 `flash --firmware ... --target-part ...` 无需初始化。省略镜像参数时可使用
  所选工程中唯一的 HEX/BIN 路径，绑定同一工程；多个不同文件要求显式选择。
- 缺型号时提示 `--target-part`；用户工作流、命令参考和 Skill 入口同步取消强制初始化。

## 验证

使用 PowerShell 7、UTF-8，通过 `scripts/build_workspace.ps1 -BuildRoot F:/MKLink-Build`。

- 初始回归出现 15 个预期失败，覆盖缺少通用参数、错误退出状态、CMake 误识别、
  保存镜像的复用和缺型号提示；实现后首轮 100 项通过。
- 独立代码审查发现已有目标配置的迁移风险；补充原文件逐字节不变的冲突测试。
  同时验证非对象 JSON/损坏 JSON 在连接前失败。4 个新增用例先失败，修复后通过。
- 显式更新原有工程的文件路径仍保留 IDE 类型和工程目标，新增用例先失败后修复。
- 最终 424 项通过，覆盖通用/原有工程初始化、配置可移植性、共享烧录参数、
  设备烧录校验、CLI/后台任务/工程切换、算法目录、HPM HEX/ROM API、远程 API、
  用户 Skill 内容边界。Skill 长度门禁最初失败，压缩入口说明后通过。
- 实际 `python -m mklink` 子进程在离线 CMake 夹具中验证：无输入返回 1，
  显式型号与 HEX/ELF 配置返回 0，重复初始化返回 0，空型号返回 1 且原文件不变。
  固定 `PYTHONPATH` 到本工作树，避免全局 editable 入口引用旧版本。
- `git diff --check` 通过；项目记忆渲染与校验在收尾时执行。

本地证据位于构建根的 `artifacts/v050-project-init-20261110/`：
`affected-tests.xml`、`offline-smoke.json` 和复现脚本。含测试链接的临时运行目录
由构建入口保留并告警，没有强制删除。

## 验证范围

本轮没有连接/烧录真机，没有重建或覆盖安装桌面包，也没有执行全量发布门禁。
共享命令与设备处理使用受控夹具验证，不作为新的 STM32G071 真机烧录证据。
当前已安装包仍是此前的普通用户安装候选；本次 CLI 改动需使用新源码或后续构建包。
