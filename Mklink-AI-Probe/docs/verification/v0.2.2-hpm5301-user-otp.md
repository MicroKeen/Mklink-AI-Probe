# HPM5301 user OTP qualification — 2026-09-18

This stage qualifies user application words 69–79 on the connected HPM5301
revision with V4 HPMLink, plus the user-group permanent write-protection test
described below. It does not qualify lifecycle transitions, debug disable,
keys, boot configuration, other silicon revisions or other HPM families.
Public security configuration remains read only outside the bounded user OTP UI.

## Implementation

The SDK 1.11.0 HPM5301 OTP table and HPM5300 manual identify words 69–79 as
application storage. Word numbers are multiplied by four: word 69 maps to
FUSE 0xF3050514 and SHADOW 0xF3050114. The implementation reads both separately.
The firmware validates the actual chip identification, permitted word range,
hard/soft locks, expected old value and one-way bit transition before invoking
the target ROM OTP program entry with a one-word delta. It validates again
after reset. No generic probe-local OTP write is used.

The target is reset/halted, the ROM call uses target ILM scratch and stack, and
the target is restarted afterwards. Interrupts are disabled during the ROM
call. Completion, return status and fuse readback are checked. Cleanup relocks
OTP and disables its programming LDO. Timeout/readback errors are surfaced
without retrying a programming request.

Initial CLI-side programming worked with the explicitly selected 4 MHz profile.
The first Chrome attempt using the GUI connection failed at the post-reset SBA
guard, before the ROM call; fresh readback still showed the old value. Firmware
now temporarily selects the qualified 4 MHz profile for OTP and restores both
the requested clock and fast DMI profile on return. The subsequent Chrome burn
passed. This verifies the workaround on this board; it is not a high-speed OTP
qualification or an electrical timing measurement.

WebGUI: Offline Flash → HPM5301 → V4 → Option Bytes / OTP → HPM5301 User OTP.
Read the current words, enter a desired value, validate/generate the guarded
script, then explicitly confirm the irreversible operation. Any edit invalidates
the plan. Duplicate submissions are disabled; errors require a fresh read.
The standalone script is displayed for inspection; U-disk script execution has
not been independently qualified in this stage.

## Replacement blank chip

The user replaced the target with another HPM5301 dedicated to fuse testing.
The probe validated its supported silicon identity and all user words 69–79
were zero and unlocked. The existing SES Debug test project build completed;
its 34,996-byte BIN was programmed at 0x80000400 through HPM ROM API with full
readback verification. The build signature was correct and the application
tick advanced from 4092 to 4330 during the initial run check.

Chrome then programmed the last allowed user word, testing both address and
unsigned-value boundaries:

| Connection profile before OTP | Word | Transition | Result |
| --- | --- | --- | --- |
| 30 MHz | 79 | 0 → 0x80000001 | ROM status zero; verified |
| 20 MHz | 79 | 0x80000001 → 0x80000003 | Bit 1 added; previous bits preserved |

OTP transactions themselves use the temporary 4 MHz profile. These results
must not be described as 20/30 MHz fuse programming. Fresh GUI readback showed
FUSE and SHADOW both 0x80000003. Words 69–78 remained zero. The shared backend
also passed same-value/no-ROM programming, invalid words 68/80, stale expected
value and attempted bit-clearing rejection. OTP read back LOCK, programming
LDO was off, the application tick advanced, and the entire Flash image still
matched the BIN after both burns.

At this stage the replacement chip had exactly user word 79 bits 31, 1 and 0 programmed.
Security fields and permanent locks had not yet been exercised. Evidence is retained
separately from the first chip's captures in the local `new-chip` report folder.

## Permanent user-group protection and independent UART

With explicit authorization for irreversible tests, Chrome programmed HARD_LOCK
word 0 from 0x30400016 to 0x30480016: only bit 19 was added, protecting user words
76–79. The API and firmware expose only complete user groups 18 (72–75) and 19
(76–79). Group 17 is excluded because it also contains non-user word 68.
The generated script uses `hpm.otp_user_lock(group, expected_hard_lock, commit)`;
the expected value, chip identity and hardware/software locks are checked again
after reset. No arbitrary HARD_LOCK mask is accepted. The data path still uses
the temporary 4 MHz transaction profile and never retries programming.

| Actual hardware check | Result |
| --- | --- |
| Chrome lock preview and confirmed write | Only bit 19 added; exact HARD_LOCK readback passed |
| Fresh GUI read | Words 76–79 locked and readable; words 69–75 unlocked |
| Target-side direct ROM attempt to add word 79 bit 2 | Value remained 0x80000003; hardware rejected the change |
| ROM return on the blocked attempt | Zero: return status alone is insufficient; exact fuse readback is required |
| Chrome control write outside protected group | Word 75: 0 → 1, verified; adjacent words unchanged |
| Target restart after control write | HARD_LOCK remained 0x30480016; words 76–79 still protected |
| GUI selection of locked word 79 | Programming-plan button disabled |
| API negatives | Locked-word write, non-user group 17, missing confirmation and stale lock snapshot rejected |
| OTP cleanup | Programming LDO disabled; UNLOCK reads LOCK |
| Independent UART0 | 115200 8N1; PA00 TX / PA01 RX; continuous sequence and 200 ms tick increments before/after tests |

The 35,388-byte test image contains an explicit one-shot RAM-triggered ROM test.
It consumes its request before execution and checks both bit 19 and the exact
word 79 baseline before attempting a single additional user bit. It never burns
automatically on boot. UART0 emits a status line every 200 ms from the main loop.
The user independently downloaded the SES image while wiring UART. Final
readback matched all three ELF load segments byte for byte. The 7,008 differences
against the flat BIN were entirely outside load segments: erased 0xFF versus
BIN zero fill. These are not reported as a full BIN match.

Final user data: word 75 = 1, word 79 = 0x80000003, all other words 69–79 zero.
Group 19 is permanently write protected; general user shadows remain governed
by their separate shadow-lock mechanism. This stage establishes reset persistence,
not a power-cycle or long-term retention test. Debug disable/lifecycle/key tests
remain unperformed. UART is now available for subsequent independent observation.

Additional software checks: 21 focused Python tests, three OTP GUI component
tests, production TypeScript/Vue build, and HPMLink firmware compilation passed.
Chrome screenshots, fuse snapshots, UART capture and direct-ROM result are kept
in ignored local reports. Qualification of group 18 is limited to the same
bounded implementation and software checks; only group 19 was burned on hardware.
