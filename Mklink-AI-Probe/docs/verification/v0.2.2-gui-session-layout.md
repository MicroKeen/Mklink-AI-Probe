# v0.2.2 GUI session and variable-path regression

Date: 2026-09-18. Development branch only; no installer rebuild or publication.

## Changes

- Long scalar paths remain on one line, without disclosure arrows or expansion boxes. Overflowing text supports pointer dragging, native touch scrolling and keyboard Left/Right/Home/End. Hover shows the complete path. Editing remains an explicit adjacent button; values and actions use a separate row in narrow sidebars.
- SuperWatch follows AI/API clock changes while preserving an unapplied local selection.
- Each acquisition restart publishes a new metadata epoch, even if channels are unchanged. Pending samples are flushed before the epoch changes. Previously an existing browser worker rejected the restarted device timeline as nonincreasing while a newly attached AI client worked.
- SystemView observes externally started/stopped captures without issuing another device start command.
- Serial display subscribes while idle, before status polling, so API-started initial output is not missed. This subscription does not open a UART.
- Python/application/Tauri version is 0.2.2; the in-app bilingual update history includes this development cycle. Published update pointers are unchanged.

## Software validation

- 176 targeted Python tests: RTT/SuperWatch streaming, stream API/hub, serial streaming and upstream integration.
- Full GUI suite: 706 tests across 66 files. Final path component and symbol-panel subset: 23 tests.
- TypeScript validation and production GUI build passed; generated GUI assets updated.

## Real browser and V4 evidence

Chrome against the source backend, MicroLink V4 and STM32F103RET6:

- Four API restarts retained the existing GUI subscriber; metadata epochs advanced 3, 4, 5, 6. Browser transport/backend drop indicators returned to zero.
- A subsequent 60-second 30 MHz shared GUI/AI capture delivered 7,344,885 samples to the observer, with zero sequence gaps and nonincreasing timestamps. Final backend CRC errors, dropped frames, read errors and dropped batches/items were zero. Parser discarded-byte counter was 188; this counter is not described as zero or equated with lost samples.
- Observer target-timeline rate was 190.62 kSa/s and host-delivery rate 122.39 kSa/s. These are different metrics; this is not a new raw-firmware speed qualification. Earlier pre-fix recording had browser timeline rejection and two CRC errors; it is retained separately and does not establish that the epoch fix repairs USB CRC faults.
- API-started SystemView became visible after the page was already open: 48,952 events, 13 tasks, 72 MHz, RuntimeDrop 0 in the captured view.
- Idle serial page received an immediate API-started shell response: 1,324 RX bytes, 6 TX bytes, terminal content visible, display drops 0/0.
- Long-path browser layout used a temporary C-layout interpretation of an existing buffer, without target writes: `_aPacket.runtime.control.reference.iq_ref_a`. A 284-pixel name scrolled inside a 207-pixel viewport to offset 77, with no disclosure arrow. Pointer capture/release and path-change reset are covered by component tests; browser keyboard navigation and rendered layout were checked. The temporary interpretation was removed by reconnecting and its absence confirmed.

Local evidence is retained under ignored `.build/reports/gui-022-live`: capture JSONL, restart metadata and Chrome screenshots. Customer firmware was unavailable; long-path preview is representative UI evidence, not a customer-hardware test.

Final state: original symbol catalog restored, UART released, 10 MHz / 1 ms SuperWatch available for viewing. Finite single-board validation does not certify every probe, board or long-duration workload.
