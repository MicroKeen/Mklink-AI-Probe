首次浏览器脚本使用 FastMCP/SDK `StdioTransport`，其 Windows Job Object 在测试客户端
退出时会清理整棵子进程树，导致页面后台同时消失；日志末尾没有正常 shutdown，
失效发现记录仍留在独立测试目录。该失败保留，不能写成“任意宿主退出都能保活”。
随后直接按 stdio 协议初始化、调用并正常 EOF，完成上面的退出码 0 与页面保活验证。
不修改或绕过宿主 Job Object 安全边界；需要跨 AI 宿主强制清理保留页面时，应使用
独立启动的桌面后台，再让 MCP 附着。首次 `gui_present(tab=serial)` 返回 422，符合
既有面板白名单；改用支持的 SuperWatch 验证，串口页使用普通 UI 导航验收。

本轮不连接下载器、不刷固件、不改目标程序；硬件由指定固件会话验收。
旧接受的性能基线与尚未闭环的时序、停止边界和客户场景保持，离线安装验证
不能代替新的硬件吞吐 A/B。现有 AI/MCP 会话需要重新加载 Skill 或重启进程。
