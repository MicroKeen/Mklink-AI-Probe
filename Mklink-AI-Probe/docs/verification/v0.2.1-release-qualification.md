## 三仓库发布与旧版迁移

新 [MicroKeen Release](https://github.com/MicroKeen/Mklink-AI-Probe/releases/tag/v0.2.1)、[旧 GitHub Release](https://github.com/Aladdin-Wang/Mklink-AI-Probe/releases/tag/v0.2.1) 与 [Gitee Release](https://gitee.com/Aladdin-Wang/Mklink-AI-Probe/releases/tag/v0.2.1) 各含相同 7 项发布资产。两个 GitHub 全部资产及 Gitee 自动更新所用安装器、签名、Skill 已先完成匿名下载与哈希核验，再写入索引；Gitee 新上传的四项补充资产随后也完成匿名下载核验。索引逐仓库写入，不是跨站原子事务。

新 GitHub `release/latest.json` 与旧 GitHub `updates/latest.json` 内容一致，指向 MicroKeen 资产；Gitee `updates/latest.json` 保持原址并使用自身镜像资产。三端版本、源码提交、签名、文件大小和哈希均与正式产物一致。

隔离目录中的原始 0.2.0 Skill 使用旧版自带检查及安装命令，从公开入口发现并下载 0.2.1，完成哈希校验和实际升级。升级后再次检查，版本为 0.2.1、无可用更新，默认地址已为 MicroKeen `release/latest.json`。本机桌面未为此降级。本轮没有另行执行旧桌面应用内自动更新按钮的端到端测试；桌面证据为实际 NSIS 覆盖安装及签名验证。

Gitee 达到 1 GB 附件配额后，经用户明确授权，仅删除 v0.1.0 的旧安装器；已保留并校验本地备份，旧 GitHub 原件、Gitee 标签和其他附件保留。

## 审核规则与边界

按用户授权，版本发布可免第二人审批，但仍需通过完整发布验收及必需 CI。PR #2 按确切头提交合并；临时审批例外结束后，API 回读确认普通 PR 恢复 1 人审批、最后推送审批及附加审批要求，CI 和讨论解决要求保留，无绕过者。

本轮不改写探针固件、不重复硬件性能认证；ARM/HPM 的实板结论继续以各自报告的板卡、固件和测试时长为界。未验证 Site Agent 实际跨主机 GUI 会话。原始日志和校验结果保留于忽略的构建报告目录。
