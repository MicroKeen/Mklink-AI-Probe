## 后续修正：未连接完整档位与紧凑接口框

用户在首个候选上指出：未连接时仍显示旧四档，SWD/JTAG 选择框过宽。
根因是配置列表直接复用了缺少固件能力时的旧硬件档位列表，且接口框继承
全局 `flex: 1`，与频率框等宽。

修正后，未连接时配置列表提供完整 14 档：1/5/10/20/50/100/200/500 kHz，
1/2/5/10/20/30 MHz；只保存请求，不发硬件命令。连接后仍按该接口的固件能力
校验，原始硬件 `clock_options()` 和 ACK 约束保持不变；旧 JTAG 固件仍不能
应用未声明的低频。配置快照忽略已断开设备留下的旧 bridge。原 4 MHz 配置
继续保留，不会静默改写。接口框固定 90 px，频率框使用剩余宽度。

392 项相关 Python 测试及 59 项 GUI 测试通过，覆盖两接口全部离线档位保存、
断开后旧能力不限制配置、离线保存不能解锁旧 JTAG 固件、独立保存和现有 ACK
边界。测试入口因发现测试链接保留了本次临时目录，未强删。
新构建的实际安装和浏览器验收将在完成后补记；首个候选及其证据保持不变。

用户随后要求旧固件提示升级：匹配的已连接接口若只支持旧档位，显示

按钮，仅切换配置页，不下载或刷写。未连接、新固件和未匹配接口不误报旧固件。
