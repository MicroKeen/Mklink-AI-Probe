# 在线读取连接失败提示

2026-10-30，产品提交 `6ce79923`，位于共用 `codex/v0.4.2-fixes` 分支。
用户确认此前 V3/H7 读取失败时未接目标板，接上后能够读取；本次只要求改善失败提示，明确无需重新构建安装包。

## 原因与改动

现场日志显示 `iter_memory → backend.connect → CONNECT_FAIL / No ACK`，尚未读取数据。
流式接口先开始成功的二进制响应，再执行迭代器中的连接；异常发生后已无法通过普通 HTTP 异常映射返回原因。
直接接口可留下空的 200 响应，经共享采集暂停/恢复封装后则表现为通用 500。

新响应先在工作线程取得首块，再提交二进制响应头。连接/首读失败沿用结构化错误映射：
`CONNECT_FAIL → 502`、`PROBE_BUSY → 409`、`MKLINK_DAP_NOT_FOUND → 404`，保留路径脱敏。
正常读取继续流式传输；首块只发送一次。不自动重试、不修改时钟或复位目标。
取消、首读失败及中途读取失败均关闭迭代器、释放原目标会话；已经发送的数据不拼入 JSON 错误。

界面中英文提示分别覆盖芯片无应答、其他连接错误、下载器占用及设备未找到。
No ACK 的中文提示为：

> 连接目标芯片失败：SWD/JTAG 未收到芯片应答（No ACK）。请确认目标板已连接并供电，检查 SWD/JTAG 接线；必要时降低调试频率后重试。

错误同时显示在读取区域与任务日志中，失败结果不作为成功数据保存。

## 验证

- 新增六个连接错误场景先在修复前复现失败，再在修复后通过；覆盖直接接口与采集恢复封装。
- 211 项 Python 回归通过：在线接口、任务资源释放、采集暂停/恢复；包含发送头前取消、首块后取消和中途读取失败清理。
- 15 项读取组件测试通过，包含八个中英文错误场景；确认错误日志、保存禁用和请求不重试。
- Vue/TypeScript 检查通过。
- 将真实源码读取组件编译到 F 盘隔离页面，与真实 API 路由和采集恢复封装联调，只有设备返回值使用夹具。浏览器确认 No ACK 返回 502、占用返回 409，并显示明确原因；正常两块共 8 字节读取达到 100% 且允许保存。
- 隔离服务已关闭，5189/8819 端口释放。证据位于 `F:/MKLink-Build/artifacts/read-error-20261030`，截图及原始日志未提交仓库。
