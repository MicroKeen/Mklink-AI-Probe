# 客户连接 500：任务日志访问被拒绝

2026-11-13，按客户截图和诊断 ZIP 做只读分析，未修改运行逻辑或操作客户设备。原始文件只留本地；下列路径省略账户和下载器标识。

## 确认事实

- 诊断包 manifest 标记 Windows / AMD64、版本 **0.4.3**，生成于 2026-11-13 17:58:17 +08:00。未提供构建提交，不能仅凭版本号确认具体候选。
- 五个失败后台共记录 60 次 `/api/runtime/select` 失败：**59 次 PermissionError** 指向 `%LOCALAPPDATA%/Mklink AI Probe/runtime/probes/<probe-id>/jobs.json`；另一次提示没有找到支持的下载器。主要异常是 `[Errno 13] Permission denied`。
- 这些失败后台均没有 `connection.opening` 事件，说明该批失败发生在实际打开设备串口之前。截图“后端正常”只表示服务在运行，不表示连接请求成功。
- 历史日志包含成功连接，最近一次为当日 09:47:12。随后多个后台重启仍遇到同一任务日志访问异常；反复点击连接不能消除文件访问限制。

## 源码对应与处理建议

官方 `v0.4.3` 的 `prepare_probe_journal()` 在切换下载器时恢复并写回历史任务；读取 `jobs.json` 的 PermissionError 未被捕获，因此向 GUI 返回通用 HTTP 500。此行为与此前 Issue #75 相符。

修复提交 `fc1c1e5b` 随 PR #76 合入，已是刚构建的 **V0.5.0 / 3a3fb298** 的祖先。当前 `RuntimeJobs._restore()` 捕获拒绝读取并保留“历史未知”状态，连接可以继续；烧录 / 擦除等依赖任务历史的请求仍受保护，返回明确的 503 提示，避免覆盖未读记录或重放未知结果。

建议客户使用已完成本地验收的 V0.5.0 候选，完整退出旧上位机和相关后台，使用 Skill / MCP 时重载对应进程，再重连。若仍提示任务历史不可读，应在客户电脑核对该文件及父目录权限、占用等信息并保留原任务记录。诊断包没有 ACL、文件占用或安全软件事件，**不能确定访问限制由什么造成**，也不能宣称升级会自动修复原文件 ACL。

本地不是客户现场；没有改变客户权限、删除客户日志或验证其设备连接。V0.5.0 仍未正式发布。
