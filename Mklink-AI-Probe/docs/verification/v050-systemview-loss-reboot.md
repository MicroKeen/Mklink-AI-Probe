# V0.5.0 SystemView 数据、滚动与采集中重启

2026-11-14，最终产品提交 `eeb29e31`（含 `c10ad7dc`），继续 `codex/v0.5.0-fixes` / PR #79。
用户明确同意修改 STM32F103 测试应用、重编、刷入；下载器固件保持 V4.7.4。
本轮不合并、不签名、不发布。最终 Windows 包已覆盖安装并复验。

## 结论与修改

- CH1 是测试程序的 RTT 文本，SystemView 实际使用 CH2。错误通道可产生 Raw 事件，
  不代表有效任务流。界面收到较多事件仍无任务时提示核对通道，不擅自切换通道。
- 本机目标 UART5 优先级实读为 `0x10`，原 SystemView 使用 `BASEPRI=0x20`，
  共用静态事件缓冲能被高优先级 UART5 中断重入覆盖。AXF 反汇编和原始流一致支持此结论。
  在目标配置及随 Skill 提供的 RT-Thread 模板中改用 RT-Thread 的中断保存/恢复锁。
  Cortex-M 端使用 PRIMASK，嵌套保留原掩码，不修改 UART 中断优先级；NMI/fault 不记录。
  模板同时遵守 `PKG_SEGGER_SYSVIEW_RTT_CHANNEL`，不再强行使用 CH1。
- 目标实际 `rtconfig.h` 仅使用 1 KiB Trace RTT 缓冲，`.config` 却记录 16 KiB。
  两者同步为 8 KiB，保留非阻塞记录。最终 Code 96968、RO 19872、RW 2680、ZI 37752 字节；
  64 KiB SRAM 中静态 RW+ZI 为 40432 字节，9 个任务均正常启动。
- “时间窗口”是可视时间跨度。画布默认 60 FPS 调度，按实测绘制耗时自适应；
  对已收到的数据范围作匀速过渡，不补造事件。统计表最多每 200 ms 重算，
  主线程不再反复合并和排序旧的降采样区间；历史保留及视窗抽取由 Worker 负责。
  短窗口查询同时保留动画尚在显示的左边缘，额外范围最多一个窗口，避免提前裁剪闪空。
  暂停后仍可缩放、平移，检查时取新统计，不把采集暂停与显示暂停混淆。
- 显式重启所选 MKLink 进入连接生命周期通道，停止其 RTT、SuperWatch、VOFA、
  SystemView 后发出一次重启命令并退役目标会话/代次、释放占用。其他下载器和独立 UART
  会话保持隔离，不自动重连或重放操作。Web/API/Runtime MCP 使用相同行为并同步说明。

## 数据证据

同一普通 V4 / STM32F103RC，下载器固件未更换。直接 Device 读取并保存原始二进制：

| 目标应用 / 条件 | 时长 | 事件数 | 解析丢字节 | ISR |
|---|---:|---:|---:|---|
| 原锁，30 MHz | 12 s | 181624 | 121 | 15、69 及 390/485/486 等异常值 |
| 原锁，10 MHz | 12 s | 181576 | 127 | 15、69 及 486/487/495 等异常值 |
| 仅修复锁，10 MHz | 12 s | 181135 | 0 | 15、69 |
| 仅修复锁，30 MHz + RTT CH0/1 | 60 s | 907271 | 0 | 15、69 |

以上 MUX 序号缺口及接收队列丢弃均为 0。原流按 1/7/64/511 字节重新分块后结果一致，
不支持“主机分块边界导致解析损坏”的猜测；本轮未通过过滤 ISR 或忽略错误来掩盖问题。

修复锁及 8 KiB 缓冲后，共享后台 30 MHz 下各约 60 秒：

| 并行采集 | 事件数 | 解析丢字节 | 目标溢出 | 相对目标丢包 | 任务 |
|---|---:|---:|---:|---:|---:|
| Trace CH2 + RTT CH0/1 | 1050783 | 0 | 0 | 0 | 9 |
| 上述 + 4 float SuperWatch，1 ms | 1061560 | 0 | 0 | 0 | 9 |
| 上述 + 4 float SuperWatch，1 µs | 1431324 | 0 | 5 次 | 895 | 9 |

三路最大负载仍存在目标端溢出；MUX 和主机接收完整性计数均为 0。
已同步固件会话检查 watch/RTT 调度公平性及背压，暂不能将其归因到某一层。
1 ms 仅为明确的对照测试，不自动降低用户配置，不宣称所有负载无损。

固件会话后续静态复核（源码 `ebb15cebfb0fc1072bef483e3fea403046ac70e3`）：

- 正常调度交替服务 Watch 和单个 RTT 通道，不存在固定 80 ms 停顿，但没有每通道
  最大服务间隔保证。四 float Watch 单轮最多 24 组，1 ms 预算在完整组后检查；
  RTT 已协商每轮最多 480 字节，环尾或小包仍消耗轮次。
- 共享 USB TX 环为 8 KiB；满时保留 pending 帧并暂停目标流读取。持续背压的总时间
  不受单次等待上限约束。RTT 错误后的 200 ms 内部恢复、半帧命令超过 500 ms 的超时，
  以及 DAP 竞争也可能延长服务间隔。现有上位机 `auto_retry_count=0` 不能排除内部恢复。
- 现有快照没有逐包设备读取时间或固件错误计数，无法将 5 次溢出定位到上述任一路径。
  平均消费不足或生产突发也可造成溢出，不能倒推出曾连续约 80 ms 没有读取。
  约 60 秒的快照实验包含 API 调用时间，不据末份累计字节计算精确链路吞吐。
- 下一轮优先记录现有 `0x40` CH2 事件的设备毫秒时间戳、长度/序号与主机单调到达时间，
  并低频读取 `0x10` 固件错误和 `0x14` 批次耗时，区分读取间隔、内部重试及主机排空延迟。
  如证实调度不足，再比较按积压/等待时间服务或缩短 Watch 批次；保留 DAP 优先和所有
  通道的基本服务机会，不给 CH2 写死优先级，不将持续 USB 背压误当轮转问题。
- 固件会话报告六项已有离线回归通过（MUX runtime/scheduling/protocol、RTT channels、
  SWD RTT scope、USB console TX）。本次仅静态与模拟证据，没有改固件、RAM 布局或操作设备，
  不改变上述实物结论，也不改变最终安装包。

最终新 AXF 的 117760 字节 Flash 段与板上回读一致；每次写入前后完整读取 256 KiB，
保留引导区及烧录扇区之外内容。最终全 Flash SHA-256：
`8e1c99bc36d4b3d20dcbb450da28a81f23892d14132cb9c3b9df24ee45ce1e41`。
新 AXF/HEX/BIN 已同步回原测试工程，原输出/配置及初始完整 Flash 备份保留。
原符号旁 SuperWatch 配置哈希不变；不提交目标二进制、硬件身份或本地工程路径。

## 限制与本地证据

本轮目标与上位机修复不构成所有 RTOS/MCU、所有高事件率或长期运行的无损保证。
未测 HPM/FreeRTOS 实物、NMI 中记录、全部串口/Modbus、外部调试器共存或完整发布门禁。
真实浏览器功能检查和调度测试不等于已测得恒定 60 FPS；保留硬件/窗口负载影响。
旧 0.4.3 性能门限不在本轮改写。本轮目标缓冲变更有用户明确授权。

本地证据目录名 `v050-systemview-loss-20261114`：原始流、分块回放、寄存器读数、构建日志、
Flash 前后回读、三组共存计数、重启 HTTP 结果、源/目标备份及软件测试日志。
目标工程构建快照包含 AXF 调试路径，保留该目录直到用户重新编译原工程。

安装版初验中，后台健康提示曾短暂显示离线后自行恢复，期间 Trace 继续接收且无解析丢弃；

不以此证明长期多视图低延迟；保留该 UI/主机负载边界，未放宽健康判定来隐藏它。
