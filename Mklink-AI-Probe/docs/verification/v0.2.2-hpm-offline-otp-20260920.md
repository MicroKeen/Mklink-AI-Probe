# HPM5301 脱机下载后用户 OTP 验收

日期：2026-09-20。HPMLink V4、全新 HPM5301、hello_world 测试程序。仅验证用户 Word69–79 与永久组锁18/19，不包含安全生命周期、调试禁用或其他系列认证。

## 执行门槛与修复

带 OTP 配方的脚本先检查 `hpm.program_verified()` 能力，再核对当前芯片、旧值与锁状态。所有镜像下载和独立逐字节 Flash 回读校验完成后，才写用户字段；所有字段成功后，最后逐组加锁。失败立即退出，不自动重试。普通无 OTP 配方仍兼容 `hpm.program()`。

探针新增 `program_verified` 能力入口；HPM5301 与其他 HPM 路径共用完整文件回读校验。空文件、非法地址范围、文件读取异常、编程/校验及最终复位失败均返回非零。旧固件没有新 API 时，实测 Pika 停止脚本，未执行后续擦写。

GUI 默认关闭脱机 OTP。修改配方会撤销不可逆确认；说明明确区分在线立即写入和部署后脱机执行。使用真实 Chrome 完成预览、部署、触发和第一次写入后的 GUI 回读。

## 本轮实板证据

| 项目 | 结果 |
|---|---|
| 初始用户区 | Word69–79 均为0，未锁；HARD_LOCK=0x30400016 |
| 固件完整性 | 38,364字节 BIN 下载后独立全量读回一致 |
| 旧固件缺少能力 | 缺少 API 时停止，后续标记未执行 |
| 旧值不匹配 | 预检停止，用户 OTP 不变 |
| 首个文件缺失 | 停止，用户 OTP 不变 |
| 第二个文件缺失 | 第一镜像成功后停止，用户 OTP 不变 |
| 第一次 GUI 脱机写入 | Word79：0→1，GUI 熔丝/影子回读均为1 |
| 第二次 GUI 脱机写入 | Word79：1→3，Word72：0→1，均 ROM 返回0 |
| 永久锁顺序 | 组18后 HARD_LOCK=0x30440016；组19后为0x304C0016 |
| 最终独立回读 | Word72=1、Word79=3，其余用户字为0；熔丝与影子一致；72–79显示已锁 |
| 锁后预检拒写 | Word72 请求1→3、Word79 请求3→7，commit=0 均返回-5，状态不变 |
| UART0 | 加锁后连续心跳 seq357–372、tick71600–74600，程序仍运行 |
| 真正断电保持 | 用户确认实际断电后，Word72=1、Word79=3、HARD_LOCK=0x304C0016保持；全量固件回读及UART心跳通过，GUI重新读取值/锁状态一致 |

锁后拒写本轮验证的是固件预检，不冒充绕过预检后的 ROM 硬件锁测试。既有在线锁区 ROM 拒写证据见历史报告。

首次测试脚本将锁拒绝码误写为-1，实际返回-5；查阅固件确认其为锁定拒绝码，修正测试断言后通过。未再次执行 OTP 提交。

## 软件验证与发布边界

针对性 Python 126项通过，GUI 26项通过，生产构建通过。故障注入覆盖能力缺失、两文件失败、两用户字失败、两组锁失败及推进 HARD_LOCK 预期值。

本轮全量 Python：2294通过、2跳过、12失败。12项均在创建测试用符号链接时遇到 Windows `WinError 1314`（缺少权限），用户授权启用开发人员模式后，原12项独立补跑全部通过；合计2306通过、2跳过。没有把受阻测试改成跳过。全量 GUI：69个文件、720项通过。

Rust 此前的 `0xc0000139` 定位为测试可执行文件没有 Common Controls v6 清单，却导入了 `TaskDialogIndirect`；系统默认 DLL 不导出该函数。构建脚本补充 MSVC 清单依赖后，PE 中可检查到 v6 依赖，19项库单元测试全部通过。随后完成的标准包构建和覆盖安装结果见下节。

后续打包发现主程序已有 Tauri 资源清单，通用嵌入参数导致重复 MANIFEST 资源。对主程序保留原 Tauri 清单、只让缺清单的测试程序生成依赖后，完整 `cargo test` 与标准 NSIS 构建通过。
