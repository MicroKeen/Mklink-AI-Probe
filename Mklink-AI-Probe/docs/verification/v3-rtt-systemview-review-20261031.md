## 吞吐及原有速度

同一普通 V3、H7 和目标镜像、同一候选源码，SWD 30 MHz，仅订阅 RTT CH1，16 KiB 环形缓冲、阻塞模式，每次 10 MiB。主机持续消费原始字节。旧、新固件各两个块尺寸的 40 MiB 数据全部重新核对字节、序号、SHA256、计时及吞吐计算；旧量子为 128，新量子为 480。

| 目标块尺寸 | 旧版主机 KiB/s | 新版主机 KiB/s | 倍率 |
|---|---:|---:|---:|
| 1024 B | 124.37 | 810.48 | 6.52× |
| 2048 B | 124.36 | 810.43 | 6.52× |

SuperWatch 4/16/64 B 各两轮、每轮 10000 组，旧新合计 120000 组数据、序号和时间戳计算均核对。组速率变化为 +0.52% / −0.07% / −0.35%；4 B 新版约 261979 组/s，不写成 300 k 组/s。16/64 B 的整组速率不能换称单变量速率。

单次读取追加新→旧→新交叉对照，10/30 MHz × 4/64/4096 B，每项每轮 100 次；1800 个保存的耗时重新计算中位数，与摘要一致。末轮相对旧版约 −3.14%～+1.53%，未见一致延迟回退。此为包含调度、后台、USB 和解析的端到端 SDK 延迟，不是纯 SWD 耗时，RTT 吞吐也不代表单次 API 延迟保证。

阶段标签由 UI 动作后的控制文件更新，不与 DHCSR 原子采样。旧 V4 核对脚本要求断点标签区间第二点起全部 halted，在 V3 最后一个已恢复运行的点触发断言，失败日志保留。V3 核对明确记录四个仍标为 running-start 的停核点及一个仍标为 keil-breakpoint 的运行点，按实际 DHCSR 核对稳定区间；不将整个 20.867 秒断点标签区间宣称为严格停核，也不删除过渡样本。

本轮开始的 Keil 列表是 0..7 禁用、8 启用，收尾最后一次 BL 与初始九条内容和状态完全相同，本轮测试 9 号已删除。此前 2→9 个条目的来源仍未定因；本轮恢复成功不撤销 [此前配置变化的记录](h7-fpbv2-systemview-idle-20261031.md)。固件会话报告已退出调试、后台 not_running；本会话没有重新查询活跃设备。

## 验收边界

普通 V3 不支持 HPM，本次没有移入 HPM 的 JTAG/SBA/DMI 实现。Keil 独立 CMSIS-DAP 并行不放宽共享断点 API 的 quiet gate，共享 step 未由此单独认证。

这是所列条件的限定验证。V3 历史掉线根因、双核实板、真实 UART 吞吐、USB 断电冷启动及全型号矩阵未由此关闭；前一天旧构建的 30 分钟空 RTT 不算新固件重验。可选 pyOCD CoreSight 枚举的 invalid CIDR / component entry 5 告警保留。没有与 J-Link/ST-Link 进行现场 A/B，不保证其他接线、MCU 或并行负载达到单路峰值。

本轮只补充交付证据；没有更换已安装上位机/Skill、修改候选或固件，也没有发布正式升级渠道。
