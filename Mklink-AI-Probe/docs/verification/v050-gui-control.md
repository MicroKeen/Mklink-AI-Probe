# V0.5.0 桌面 / Web GUI 共享控制与多窗口验收

日期：2026-11-14。产品提交 `ba3a334b`（主体 `a05f546f`），普通用户 Windows 覆盖安装已完成，未签名、合并或发布。

## 变更

- MCP 增加 `gui_control`，CLI/SDK 共用 `gui_windows/gui_snapshot/gui_action`。
  使用已有窗口的 presence WebSocket，显式选择窗口；不另开探针连接。
- 5 个主页面、4 个配置分区、8 个仪表盘标签均可导航。可查询页面真实状态、
  枚举控件、输入/选择/点击、请求前台、操作 Timeline 和回放。控件按原有处理程序执行。
- 控件 ID 仅属于原窗口；路由、探针身份、设备代次或控件状态变化后拒绝旧指令。
  禁用/只读和确认保持有效，不接受任意 JS/选择器；未确认结果不自动重发。
- 文件导入是有界、单次、绑定窗口的通道。超时或窗口消失释放文件句柄，
  AXF/ELF 原路径保留，同目录配置和同路径重编检测不会变成临时上传副本。
- SystemView 导入回放只退订当前窗口，返回实时重新附着；其他窗口和共享采集继续。
  RTT/串口历史 RX/TX 仅显示，不重发到设备。SuperWatch 沿用现有 Worker/图表。
- Skill 增加 [操作说明](../../references/gui-control.md)，完整包与本机 Skill 副本同步。
  原有设备、日志导出/转换接口继续使用；本协议不控制操作系统文件保存对话框。

## “后端离线但事件更新”的根因与验证

此前 `7b2da4f3` 的历史增量淘汰及健康检查去重有效，但安装版仍能复现假离线，
不能把此前直接 HTTP 健康请求成功当作浏览器状态通过。

同一浏览器打开 6 个 SystemView 页面时，每页的长期状态 SSE 占用 HTTP/1 连接；
普通健康请求在浏览器连接池排队超时，独立的二进制 WebSocket 仍更新事件。
修复前真实页面状态采样从 alive 变成全部 dead，事件仍由约13万增长到48万。

SystemView 本已有每秒一次的状态轮询来发现其他客户端启动/停止；现在由该轮询
统一更新任务名、CPU频率、记录状态、错误与丢弃计数，删除重复状态 SSE。
不延长健康检查超时，不用事件更新掩盖实际健康失败。原 SSE 后台接口保留兼容。

修复后源码 6 Web 页面、最终安装版桌面 + 5 Web 页面，均通过 12 轮窗口状态采样，
72/72 alive；操作通过真正 MCP 工具发往窗口并取得回执。安装版冻结 MCP 有59个工具。
浏览器测试工具只负责启动、截图与错误观测；没有 Computer Use，也未用 DOM 注入替代控件操作。

## 实物与操作验证

普通 V4.7.4 / STM32F103RC，SWD10MHz，沿用此前 IRQ 锁和8KiB CH2缓冲，未刷写或改供电。
Trace CH2、RTT CH0/1、四变量 SuperWatch 1ms 并行；最终快照：

- SystemView 645064 事件、9 个任务，解析丢字节、目标溢出及主机队列丢弃均0。
- SuperWatch 实测约 992.90 Hz；RTT 开启但本轮没有文本载荷，不宣称有载荷吞吐通过。
- 桌面置前、全部页面/控件枚举、0.5/10/60秒窗口、暂停缩放/继续通过；只操作所选窗口。
- SystemView JSONL：导入、暂停、10倍速、重播至1000事件、缩放/全览、返回实时通过。
- RTT：导入、播放/暂停、倍速、源通道切换、定位、退出通过；包含RX和TX的夹具未向硬件发送。
- SuperWatch CSV：导入、定位、倍速、返回实时通过；串口日志导入/定位/退出通过。
- 桌面原生和 Web 分别执行回放。另在一窗口回放时验证后台事件继续增长，另一窗口仍为实时。
- 原生文件选择保留 AXF 原路径；测试对 Windows 路径分隔符做规范化比较。
- 全部测试采集停止，设备断开，测试原生窗口正常关闭。浏览器没有 pageerror 或健康请求失败。

串口/RS485未接线，未做实物收发、Modbus设备通信、OTP永久操作、供电切换、新Flash写入或固件升级。
这轮是 GUI 接入和已接目标的受影响验收，不等于完整发布门禁；不宣称恒定60FPS。
既有1µs三路极限共存的目标溢出边界保留，见 [前轮报告](v050-systemview-loss-reboot.md)。
