## 实测条件与口径

普通 V4、USB7 候选（固件源 `465a9b69`）、STM32H743、SWD 实际 30 MHz；沿用既有目标映像 SHA-256 `77e050914ce05b232c87d1b17855b8bd400a154b863161eb66bfe543da8653e5`。操作前核对下载器身份、占用、芯片、AXF 与地址，复用安装程序的共享后台，没有另起竞争串口后台。

- PE2：`GPIOE.IDR.ID2`，从 `GPIOE.IDR` 的 4 字节寄存器读 bit 2。
- RAM：`led_gpioe_idr`，4 字节实时非缓存 RAM 镜像。TIM7 中断翻转 PE2 后执行屏障并读取 IDR 更新镜像；它不是启动时的历史轨迹缓冲区，也不是独立 RAM 方波。原始值为 65280/65284，分析 bit 2；GUI 保留原始纵轴，没有修改原始数据。
- GUI 请求间隔固定 4 µs、显示缓冲 50000。每组单通道约 3 秒；GUI 自身二进制订阅加一个认证观察订阅，观察器只存内存，停止后保存 `stream-frames.bin` 与 `samples.npz`。正常组关闭产品 JSONL 日志。
- 平均速率按全段原始时间戳 `(N-1)/span`，间隔统计包含批内和批间。小数毫秒转换回整数微秒前验证误差小于 1e-6 µs，避免浮点舍入影响“≥40/100 µs”计数；原始文件不改。
- GUI 顶部 Hz 是宿主一秒完成量统计，缓冲排空时可明显偏离采样时间戳速率（100 µs PE2 停止时曾显示 25–26 万 Hz）；不作为本表物理采样率。GUI 最大间隔/空隙数仅统计当前视窗，本表统计整个记录。
- 40 µs 是每次翻转间隔，完整周期 80 µs；100 µs 对应完整周期 200 µs。完成两组 40 µs 测试后，停止采集，核对 TIM7 CR1=1、DIER=1、PSC=239、ARR=39，只写 ARR=99 并校验；未写 EGR/CNT、未重启、未重新编译或烧录。等待切换暂态结束后采集。此改变是用户要求的新测试信号，不是要求目标适应下载器。

40 µs PE2/RAM 平均速率与前轮 4 µs GUI 基线 142535–142547 / 236640–236909 次/秒接近。不能用该平均值掩盖长间隔，也不能把最快有限 RAM dump 约 27 万次/秒混作本条件基线。

40 µs PE2 出现 120 µs 观测边沿间隔，存在漏过完整脉冲的嫌疑；RAM 最大采样间隔 51 µs 也超过 40 µs。100 µs RAM 的最大间隔 47 µs、最大边沿间隔 142 µs，没有超过 150 µs 的观测边沿间隔，本轮未发现完整脉冲漏采迹象。没有同步逻辑分析仪，因此不宣称全部物理边沿逐个核对或长期绝不漏采。

100 µs PE2 首轮在采样时间 2453775 µs 出现 9047 µs 空隙，同轮另有 5810/2981/1671/644/484 µs；复测在 1869181 µs 出现 1343 µs 空隙。它们出现在采集中，不能作为开始/停止暂态剔除。关闭 JSON 日志仍能重现，根因未定位，不归因于单一日志或绘图负载。20 µs 最大间隔目标未达。

固件会话只读复核发现：上述七处 >100 µs 间隔全部满足 `(sample_before + 1) % 127 == 0`，对应当前固件单字批容量边界，前后批内仍为 6–8 µs；这些空隙都位于上位机同一个 WebSocket 数据帧内部。保存帧与 NPZ 的时间戳和值一致。因此优先排查批间 USB 发送背压和控制调度，不能归结为 GUI 分帧画线，也没有证据将其归因于目标的 100 µs 翻转。缺少原始 MUX/USB 收包时间线，具体根因仍未确定。

按 WebSocket 帧头发布时间增量减去该帧末样本设备时间增量，两轮 100 µs PE2 最大相对发布滞后为 956.146/903.507 ms；40 µs PE2 为 0.901 ms，两轮 RAM 约 22.59 ms。这个量使用墙上时钟，是相对发布滞后，不是绝对 USB 延迟。明显积压支持优先检查宿主接收/处理链背压；现有接收 worker 的有界队列满时可能阻塞，MUX 队列零新增丢弃不能排除更上游的背压。下一轮应关联单调时钟的 worker 读取/队列字节占用、inbox、bridge.feed、发布时刻与原始 MUX 事件，而不是无限增大缓存或改变目标程序。

## 完整性、日志异常与范围

正常五组保留全部已发布二进制帧，WebSocket 帧 CRC 解码、帧序连续、样本数与后台完成计数增量一致；值域和时间戳单调性通过，新增读取错误、MUX 队列丢弃字节、缺帧、残缺样本和桌面分发丢弃均为 0。这里证明已接收/发布数据链的一致性，不证明采样空隙内没有物理边沿，也不意味着固件原始 Watch v2 本身有 CRC。

另保留首轮产品 JSONL 开启的失败对照 `pe2-40us`：545336 样本，约 137191 次/秒，最大间隔 16083 µs；运行快照丢弃为 0，但停止快照累计出现 **704730 字节 MUX 队列丢弃**。该计数来自有界 Watch 接收队列，不能写成“纯解析噪声”或“全部零丢失”。以后五组计数保持 704730，按前后增量核对为零，没有清零或隐去历史异常。记录负载影响与 PE2 无日志长间隔须分别定位。

灰色空隙和断线已在实际安装 GUI 显示；缺少观测的区域不连线，不补值。当前视窗可能不含全段最大空隙，所以截图上的 22/26 µs 不能替代全段的 9.047/1.343 ms。截图没有重绘为理想方波。

本轮没有重新执行 RTT/DAP 压力矩阵。相同采集实现的前轮 USB7 配套资格包含 RTT 853.27/853.49 KiB/s（每轮 10 MiB 全字节核对）及 300 DAP + Watch + 2 MiB RTT 共存，见 [MUX 配套报告](v043-mux-sampling-contract.md)。它不覆盖本轮日志异常、所有安装环境或长期抖动；本次不得声称这些新异常已通过 RTT/调试回归。

结束时：所有测试流已停止，测试 SDK detach，原生 GUI 保持连接并展示 100 µs PE2 停止波形。TIM7 ARR=99 保持运行，复位后按现有映像恢复 40 µs。未碰 VCC/OTP、未刷探针固件。
