# SuperWatch 采样空隙可视化（2026-11-04）

本轮继续 `codex/v0.4.3-fixes`。在 SuperWatch 中增加**视窗最大间隔**、
**视窗空隙次数**和灰色空隙标记，并在空隙两侧断开曲线。产品版本仍为 0.4.2，
没有生产 Web/安装包构建、安装覆盖、合并、签名或发布。

固件采样空隙优化由专用会话 `01a1a1a2-9adc-79e2-b30e-07c07d5f90c6`
执行。目标是压缩 GPIO 和普通 RAM 的批间、批内长间隔，并用逻辑分析仪
核对 PE2 每 40 µs 翻转时是否漏采。不得修改目标程序来适应下载器采集。
最大间隔小于 20 µs、40 µs 翻转不漏采及最终固件性能资格尚未完成。

## 统计与显示语义

- 仅使用携带逐点时间戳的 SuperWatch 数据；相邻原始采样包含跨批次边界。
  不用前端接收时刻、平均速率或绘图抽点之间的距离推算采样空隙。
- 统计范围是**与当前视窗相交的原始相邻采样区间**，包含跨越视窗边界的区间；
  视窗完全处于两个采样之间时也能标灰。它不是整场采集的累计最大值。
- 标记阈值为 `max(20 µs, 2 × 设置采样间隔)`。4 µs 设置对应 20 µs；
  正常低速采样不会全部标灰。阈值比较保留 1 ns 浮点容差。
- 灰区表示没有观测值，不等于目标信号的高低状态；空隙次数不等于漏边沿数。
  不补点、不插值恢复丢失边沿，不改变原始记录和导出值。
- 在 Worker 的可视包络计算中合并时间统计；绘图只接收按像素限定的标记和
  断线段号。按采样行统计一次，抽点后再分配各通道段号，避免对每个通道重复
  执行逐样本断线判断。临时空隙索引受保留样本数限制。
- 暂停使用冻结的时间戳与数据；新元数据、清空、重连或设备切换不会沿用旧统计。
  旧后台估算时间戳、混合旧格式历史、日志回放及单次触发的独立捕获显示 `—`，
  不把不可用的统计显示为零。无相邻区间时最大间隔显示 `—`。

本轮只修改 GUI 源码；CDC/MUX、普通读取、调试准入、RTT 接收与固件没有由
本会话修改。采集接收路径只为每批记录时间戳是否为逐点格式，统计在视窗请求
时执行。仍需测量渲染开销，不能把没有修改传输代码等同于端到端性能保证。

### 40 µs 翻转的同步证据

`baseline-wave-ec185ffc/gpio32-wave-gpio-analysis.json` 对应 500 MS/s
原始逻辑分析仪波形 `gpio32-wave.kvdat`，SHA256
`4a7e4c0cc8f5b504cb62fdd1ff932ffa2c8bc6d7c51c7f0ea534a43f846c35a7`。
通过 SWD 帧和奇偶校验确认 CH0=SWCLK、CH1=SWDIO、CH2=PE2，纠正旧通道标注。

- 100203 个有效 GPIO RDBUFF 读，奇偶错误 0。
- PE2 物理相邻边沿 P50 40.000 µs、范围 39.848–40.142 µs。
- 排除 7901 个“读取窗口内恰好发生翻转”的歧义读，稳定读窗口值与 PE2 不匹配 0。
- 在 84403 对无歧义相邻读取中，以下四对各跨过两个物理边沿，读取值却没有变化，
  因而**至少漏采 4 个完整脉冲 / 8 个物理边沿**：

| 后一个读取的索引 | 读启动间隔 µs | 物理边沿 | 观察到的变化 |
| ---: | ---: | ---: | ---: |
| 33019 | 50.994 | 2 | 0 |
| 39623 | 57.228 | 2 | 0 |
| 41782 | 81.694 | 2 | 0 |
| 93598 | 76.174 | 2 | 0 |

这是已确认漏采的下界，不能将被排除的歧义读算作通过或据此给出全量漏采率。
读取窗口自身最大 53.992 µs，读启动最大间隔 81.694 µs，仍需固件阶段分析。

固件会话随后刷入临时阶段诊断候选
`6fa4f507`，首次采样后查询诊断统计遇到 `Malformed multiplex frame`。
该失败已保存并退出，不算通过；临时诊断扩展不能作为正式协议或最终性能结果。
后续将临时统计缩为 192 B，未放宽宿主帧上限，14 组各 1 万点阶段诊断通过，
STOP、恢复 10 MHz、断开正常。该诊断定位到每批 USB 发送约 16–19 µs，
其中 DMA 缓冲复制/提交约 11–14 µs；每毫秒 USB 维护任务的平均抢占约
13–20 µs。固件会话正在优化这些公共路径，同时保留 DAP 让出和 RTT 调度。
这些是带诊断代码的阶段成本，不是最终无诊断候选已达到 20 µs 的证据。

此前独立内存调用 P95/间隔读取稳定低于 1 ms 的目标仍开放，见
[延迟调查](v043-tail-latency.md)；本轮空隙显示不能代替该项验收。

### USB3 候选的稳定端点边沿核对

固件会话追加了 `gpio32-wave-gpio-analysis-anchors.json`：用首尾两个不跨物理边沿的
读窗口固定统计区间，再比较整个区间内物理边沿与读值变化，纳入中间跨边沿读窗口。
两组记录分别位于 `baseline-wave-ec185ffc` 与 `usb3-wave-268b73d5`。

| 同步记录 | 稳定端点间隔 µs | PE2 物理边沿 | 读值变化 | 差额 |
| --- | ---: | ---: | ---: | ---: |
| 基线 | 697645.370 | 17441 | 17429 | 12 边沿 / 6 完整脉冲 |
| USB3 | 698670.566 | 17467 | 17467 | 0 |

USB3 原始波形 SHA256 为
`05dd62680c79449507dd806ede3638e58b9fb595dec4d5eef1c8db0d6cab573c`。
宿主 100000 个样本与线上 SWD 值逐项相等，奇偶错误、稳定读值错误均为 0。
USB3 读启动最大间隔 **47.874 µs**，不能据该次区间边沿差额为 0 宣称长期不漏采，
也不满足最大间隔 20 µs 的目标。早先“四个完整脉冲”的结论是相邻无歧义对的下界，
本次端点统计将基线同一记录的差额进一步确定为六个，并未覆盖或删除旧证据。

USB3 同条件 RTT 约 824 KiB/s、GPIO 最快约 14.4 万次/s；4 µs 设置仍比基线慢约
0.86%。USB4/USB5 虽通过数据校验，但 RAM 持续吞吐下降，未接纳为最终候选。
固件会话继续隔离 USB 复制、中断代码布局与批内停顿，保留原调度公平性和目标程序。
以上仍固定旧宿主源；新宿主在线协议迁移的配套资格另见
[当前采样契约](v043-mux-sampling-contract.md)。

随后固件会话报告 USB6 完整对照通过：GPIO 最快 144374–144429 次/s、
4 µs 设置 142022–142045 次/s，RAM 有限采样 269747–270821 次/s、
持续采样 262711 / 262703 次/s，RTT 853.09 / 853.05 KiB/s，均未低于本轮基线。
GPIO 最大间隔仍 **46–50 µs**、RAM 最大 **38–42 µs**；USB6 尚未补做最终宽度、
非对齐及调试共存回归，也不能继承 USB3 波形的边沿结论。USB7 继续隔离 DMA 路径，
不将此中间成绩视作最终资格。

### USB7 最终候选与新宿主配套

USB7 候选固件源在专用仓库本地提交为 `465a9b69`，宿主源固定 `1bed6807` 后另组验收。
原始记录 `integration-1bed6807/runs/usb7-wave-newhost-db6fdfe2/gpio32-wave-gpio-analysis.json`
对应波形 SHA256
`c5cb00aafee87de0c15b114323399478056bcfa042692faae67c7cfdc93f5030`。
100000 个宿主值与线上 SWD 全部一致，奇偶错误与稳定读值错误为 0；
692442.998 µs 的稳定端点区间内，物理边沿与读出变化均为 **17311**，缺少完整脉冲为 0。

该记录最大读启动间隔 **37.418 µs**，固定旧宿主 `b5d` 的另一段 USB7 记录为 **46.440 µs**。
这些单段成绩不能作为硬上限：新宿主其他有限测试仍出现 GPIO **62/65 µs**、窄读 **82 µs**。
20 µs 目标及长期无漏采仍开放；界面继续显示真实空隙，不以插值掩盖。

固定旧宿主的固件对比中，RAM 批边界中位数由 **33/34/32 µs** 降至 **21/21/21 µs**，
主组平均吞吐均提高。但 64 B 组最大尾间隔由 162 到 164 µs，并非所有尾部延迟都改善；
16/64 B 是顺序总线读，其整组正常耗时本就不能套用单字的 20 µs 目标。
新宿主 RAM 持续约 26.44 万次/s、RTT 约 853 KiB/s，数据校验和 300 次 DAP 并行通过。
准确范围与遗留资格见 [当前采样契约](v043-mux-sampling-contract.md)。
