# 灵活面板真机对照：MicroLink V4.7.3 与 V4.7.4

2026-11-21，官方标准 Web GUI，候选提交 `eecc775051414745815592a4c5613a30e285dcac`。V4.7.4 完成双窗口连续采集、同通道 RTT 独立操作和两种记录回放。双窗口的严格零丢弃指标在首次观测中未通过，在全新后台和后续重复场景中通过。[V4.7.3 原始验收](flexible-panel-integration-20261121.md)

## 相同的测试条件

- 探针连接后实际报告家族 microlink、型号 V4、固件 V4.7.4。COM4 对应的探针身份、STM32F411 开发板芯片唯一 ID 与上轮一致。本轮另读 DBGMCU DEV_ID 为 0x431。
- 两轮使用同一已存在的 AXF 路径，文件修改时间早于旧版基线。两轮分别对目标应用 Flash 段首、中、尾各抽读 16 字节，与相同位置的 AXF 内容相符。SWD 时钟均为 10 MHz。
- 同一组六个 SuperWatch 变量、GUI 回读采样周期 0.020 s、同一个 RTT CH0。两轮均由同一候选分支的默认生产资源提供 GUI，通过真实浏览器操作。使用独立测试工程目录，原始采集文件分开保存。未刷写、复位或改动供电。

## 观察结果

记录开始和结束由同一组 GUI 操作驱动，各次录制时长不同。帧数用于校验对应文件的完整性。

## SuperWatch 丢弃及响应延迟

后续使用相同板卡和 AXF 完成了修复前后共 52 轮窗口开关，并在真机采集期间验证了主机阻塞与丢弃的关系。[长时对照及回归](flexible-panel-v474-soak-20261121.md)

1. V4.7.4 首次双窗观测中，SuperWatch worker 的丢弃指标最大为 69。同一采集会话继续观测，主机分发累计丢弃为 69 批、69 个样本投递、3,312 字节，队列峰值 64。第一窗的三个波形读者各自记录 23 个序号间断批次。各读者共享后台累计量，不能将 69 再乘以读者数量。该时段的设备采样丢弃标志、固件读取错误、解析 CRC 错误及不完整样本均为 0。
2. 在同一会话中再次开关第二窗，累计值在开窗前、双窗采集时和关窗后均保持 69；新开的波形读者在自身观测期间没有新增序号缺口。首次打点前已经发生的丢弃无法定位到具体 UI 操作。
3. 重建测试后台后，从零计数开始做相同开关窗口操作。冷启动场景和做完记录回放后的再次开窗各采了 40 个后台快照。两轮都观察到独立窗口数 1 → 2 → 1、所有剩余读者继续前进、后台丢弃从 0 保持到 0，队列峰值分别为 5 和 8。
4. 单窗操作期间 18 次本地健康请求的最大耗时，V4.7.3 为 57.03 ms，V4.7.4 首次为 1,628.66 ms，补测为 79.68 ms。包含双窗开关的较长会话各取 105 个样本，P95 / 最大耗时分别为 71.40 / 126.22 ms 与 56.11 / 100.36 ms，后端 CPU 均值分别为单核心的 45.99% 与 35.89%。两轮的主机负载和用户操作节奏没有锁定，这些数值只描述对应会话。

首次超长响应和主机分发丢弃均保留为间歇现象。当前证据可区分主机投递与设备采样计数，无法确定触发点或证明固件版本是原因。复跑期间另有一次停止指令收到明确的陈旧版本拒绝，随后读回确认采集已停止、记录已完成，并从文件完成回放。

## 证据范围

实测覆盖官方 Web GUI、同板同工程的短时采集与回放。后台、回放文件、GUI 可见状态和浏览器 worker 遥测分别取证。未做原生桌面 WebView、长时满载或降级再升级的交叉试验。
