## 安装版双设备验证

用户原有两只 V4 保持接线：MicroLink V4.7.4 / STM32F103、HPMLink V4.7.2 / HPM5301。
测试后台均由安装目录的 `mklink-sidecar.exe runtime serve` 启动；核对进程映像路径，测试脚本仅通过公开认证 HTTP / RuntimeClient 驱动，不以源码后台替代安装版。

1. 在 F 盘隔离任务目录放入非 UTF-8 `jobs.json`，HPMLink 仍能连接。查询任务返回结构化 `503 / job_history_invalid`，保留未知任务保护，原文件字节不变。
2. 第一窗口连接后再启动第二后台连接另一设备；两个后台 PID / HTTP 端口独立，第一设备连接代次不变。
3. 第一窗口选择第二窗口占用的设备，返回 `409 / probe_in_use`，两个既有连接均保持不变。
4. 第二窗口正常断开后，第一窗口 HPMLink → MicroLink → HPMLink 往返切换成功，后台 PID / 实例 / 端口不变，异常任务文件仍保留。
5. 指定不存在的设备身份返回 `409 / probe_missing`，不改连其他设备，当前连接保持。
6. 所有连接通过正常断开和后台停止接口释放，进程退出码 0。未刷写、复位、修改供电、写目标 RAM 或启动采集。

验收脚本首次请求 `/api/runtime/jobs` 缺少尾部 `/`，严格 HTTP 客户端把重定向空体当 JSON 解析而中止；后台正常清理。改用已声明的 `/api/runtime/jobs/` 并新建隔离目录后以上检查全部通过。该修正只涉及验收脚本。
