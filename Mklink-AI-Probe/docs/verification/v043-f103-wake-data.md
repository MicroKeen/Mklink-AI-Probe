# 0.4.3 普通 V4 上 STM32F103 睡眠后续采验收

上位机修复提交为 `2a3cbb771bd89e99375683509660f22080be7ec2`。普通 MicroLink V4.7.3 的 15:33:35 和最终编号版 16:04:46 两个构建均做了同板验证。判据是睡眠前启动的采集，在目标持续唤醒后沿用原会话继续工作，RTT 字节可逐帧核对。此前每 100 ms 醒几条指令即再次 WFI 的镜像，只验证了睡眠快照和普通流访问失败，未提供持续唤醒的对照。[第一轮候选记录](v043-release-candidate-acceptance.md)

## 同一次启动的对照

临时 F103 验收程序先持续运行，收到一次 RAM 触发后转为约 7.5 s 的 WFI，每 100 ms 由 SysTick 唤醒，最后恢复持续运行。RTT 每帧 12 B，含阶段、递增序号和校验字。目标维护实际提交帧数和环满次数。在预期的数据承载范围内，256 B 环会多次回绕。SuperWatch 按目标采样时间观察 `sample_counter`。测试结束后恢复原 100 ms WFI 镜像，刷写校验成功，再独立比较 `0x08005000` 起的 1024 B，全段一致。

| 场景 | 实测结果 |
|---|---|
| 修复前，仅开 SuperWatch | 睡眠前已取得有效样本，进入 WFI 后持续返回状态 5；3 秒后上位机关闭订阅。目标持续唤醒后仍停在第 74 个周期，累计 183 次读取错误。 |
| 修复后，仅开 SuperWatch | 10 ms 采样间隔下沿用原订阅恢复。独立记录含 989 个样本，时间戳严格递增，两个相邻有效样本之间有 7.504497 s 空隙，数值由 575 变为 1326；记录中有一个真实断点。 |
| 完整 Skill 同时开 RTT、SuperWatch | 从归档中的 stdio MCP 默认打开可见 GUI，并在同一后台采集。收到序号 0–139 全部 140 帧，共 1680 B，其中 7 帧在睡眠阶段的短暂唤醒中写入。逐帧阶段和校验字正确，目标环满 0 次，接收游标无丢失或重置。SuperWatch 自行恢复，记录 1001 个样本。此轮固件没有报告读错，时间戳显示 7.63 s 观察空隙。 |
| 单开 RTT | 睡前已订阅，目标再次持续运行后自动接续。收到的 140 帧全部按序且校验正确，环满 0 次。 |
| Windows 原生 GUI | 从修复后的 NSIS 载荷启动 Tauri，页面选择普通 V4、解析本轮 AXF、勾选 `sample_counter` 并点击开始。1 ms 间隔下睡眠区间显示灰色断点，唤醒后波形继续，累计 6910 个有效周期。随后从页面停止并退出。 |
| 在目标已睡眠时第一次启动 RTT | 工作线程返回状态 5，此时没有已建立的 RTT 订阅。目标持续唤醒后显式再次启动，实际写入的 140 帧完整收到。该对照在环满时由测试程序保留待写序号，计到 95 次未成功入环的尝试；不能由此推断其他应用在环满时也会保留待写数据。 |

本次修改只针对桌面和共享后台的连续 SuperWatch。一个订阅在同一目标代次取得有效样本后，状态 5 会计入读错，采集继续等待；下一条有效样本标记断点。一直未取得有效样本的配置仍有超时保护，新的目标代次重新判断。USB 断线、调试器切换目标、复位恢复失败及有限次数的采集沿用原处理。RTT 的传输和游标、正常采样时的数据解码、探针调试仲裁均未改动。

在目标可访问的时段，以上用例已验证实际提交的 RTT 字节没有遗漏或重复。SuperWatch 保留已取得的有效样本；目标无法访问期间的变量变化没有可供追溯的样本。高速性能基线仍采用此前 V4/H7 的同负载实测，本轮 F103 结果只用于睡眠后恢复验收。[V4/H7 性能](v043-v4-iar-exit-context.md)
