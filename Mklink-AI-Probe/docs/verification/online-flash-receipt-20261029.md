# 在线烧录自动收尾与采集恢复提示修复

2026-10-29，共用 `codex/v0.4.2-fixes`，产品版本保持 0.4.1。
本次未合并、签名或发布，也未修改正式 0.4.1 资产。

## 原因与行为

在线烧录工作线程结束后，共享后台仍需恢复之前暂停的采集并保存最终结果。
原界面用“存在请求凭据”判断是否显示待确认提示，因此这段正常收尾时间也会
显示“已有待确认的在线请求，暂不允许新任务”。结果查询若短暂失败，原轮询会停止。

现场记录确认 HPM5301 烧录成功，RTT 自动暂停后恢复返回
`RTT channel is not active`；后台最终记录仍为烧录成功。

- 正常收尾静默查询，后台完成结果记录后自动清理本地请求凭据，恢复下一次烧录。
- 采集恢复失败仅写任务日志，不弹确认、不要求手动查询，不重新执行烧录。
- 结果查询短暂失败自动继续；事件流断开、提交响应丢失和停止返回终态时自动核对结果。
- 新请求清空上一任务的显示状态，避免将上一任务完成状态用于本次结果判断。
- 真正缺失或未知的执行结果仍禁止重放；已有防重复提交、跨探针隔离及人工核查机制保留。
