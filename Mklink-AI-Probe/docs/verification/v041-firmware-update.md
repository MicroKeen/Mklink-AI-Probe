# 0.4.1 固件检查、自动升级与下载名称修复

基线为 PR #60 合并后的 `87080ed8`。按维护者要求，后续 0.4.1 任务统一使用 `codex/v0.4.1-fixes`，不按单个问题另建分支。正式 0.4.0 标签、安装包、云索引和固件资产均不改写。

首批代码提交 `94dc25d7`，本交接单独保存。

## 原因与修改

- 当前运行的 0.4.0 后台保留了已拔出下载器的身份；被动枚举中出现新的唯一下载器。原检查接口返回 HTTP 409 / `missing`，而配置页静默吞掉异常。原升级接口返回无法识别下载器的手动路径。
- 固件按钮现在先根据明确的本地设备选择、仍在线的后台绑定或唯一在线设备，调用已有的独占选择事务；不连接目标板。检查/升级请求携带探针身份与连接代数，多设备不猜选，其他后台占用不接管。检查显示进行中、版本、修订及失败原因。升级后的版本由升级流程验证，不再自动选择其他新插入的设备复查。
- 桌面代理原先仅暴露 `X-MKLink-Submission` 跨域响应头。后端虽然返回正确的 `X-MKLink-Firmware-Name`，原生 WebView 无法读取，前端退回 `MicroLink_V2.uf2`、`MicroLink_V3.uf2` 等不含版本的名称。
- 代理现在暴露固件名称、版本、来源、系列和 Content-Disposition。页面采用服务端动态返回的完整名称，并验证型号和扩展名：V2 为 RBL，V3/V4 为 UF2。缺失名称或型号不符时报错，不生成猜测名称。没有设备时仍可选择型号手动下载。
