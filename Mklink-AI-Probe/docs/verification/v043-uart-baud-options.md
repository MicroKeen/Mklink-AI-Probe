# 0.4.3 串口助手按固件能力选择波特率

2026-11-06，继续 `codex/v0.4.3-fixes`，保持已接受的上位机性能基线。
用户要求普通 UART 按已适配档位选择，取消手动输入。本轮只修改源码和
Web 产物用于验证，不构建安装包、不覆盖应用或全局 Skill、不合并或发布。

## 行为

- 串口助手改为下拉选择。普通 UART 必须同时声明 `UART_BAUD_PROFILE=1`
  和合法 `UART_BAUDS` 列表，才提供固件实际声明的档位；不按版本号推断能力。
  profile 1 的 34 档为 300、600、1200、2400、4800、9600、14400、19200、
  38400、56000、57600、115200、128000、230400、256000、460800、512000、
  750000、921600、1000000、1500000、2000000、2500000、3000000、3500000、
  4000000、4500000、5000000、6000000、7000000、7500000、8000000、9000000、10000000。
- 缺少、未知或损坏的声明回到原有八个常用档位，并提示实际支持以设备为准。
  RS485、通用串口和身份不明接口不继承普通 UART 的高波特率资格。
- MI_02 普通 UART 只通过唯一 USB 序列号配对 MI_04 命令接口；MI_06 为 RS485。
  刷新串口保持被动枚举，已连接同一下载器时复用已有能力缓存，不发命令。
- 独立串口使用者可点击“读取下载器档位”。读取经同一探针的后台执行一次
  `probe_version`，查询后复查端口身份；占用、歧义或身份变化即拒绝，不抢串口、
  不停止采集、不切换当前 GUI 的目标、不自动重试。
- 已运行会话的列表外波特率作为只读“当前会话”项展示，不改写会话配置；
  停止后或切换到不支持该档的接口时，空闲选择回到 115200（或声明的首档）。
  CLI/MCP 的既有数值参数保持兼容；固件仍负责最终拒绝不支持的请求。

- Python 串口能力、USB 接口、UART 会话、共享 UART/探针查询相关集合：
  **139 passed**。覆盖完整/部分/损坏声明、旧固件、跨设备缓存、歧义配对、
  查询中身份变化、忙时单次拒绝和被动 HTTP 枚举。
- GUI 串口助手、自动化、录制、序列、发送及 API 集合：**61 passed**。
  覆盖档位读取、未知 profile、RS485 切换及已有列表外会话值。
- `vue-tsc` 和生产 Web 构建通过；产物独立存于构建根，未改跟踪的 `gui/dist`。
- 真实内置浏览器加载生产 Web：初始八档；点击读取后显示完整 34 档，
  成功选择 4M、10M；切换 RS485 后仅八档、空闲值回到 115200、隐藏读取入口。
  页面是原生下拉而非数值输入；全程仅一次模拟 `probe_version` 查询。
  测试页关闭、服务正常退出，无硬件打开。
- 最后调整未连接时的被动缓存检查顺序并补充文档后，定向复核
  **87 Python/Skill/记忆检查、11 GUI 检查通过**；与前述集合重叠，不相加。
  记忆验证和 `git diff --check` 通过，新增能力测试纳入共享后台 CI。
- 首轮 CI 为 **3813 passed / 1 failed**：远程 `serial.list` 旧断言未包含新增
  `uart_baud` 元数据。补齐精确返回值和“不查询硬件”断言后，相关 **89 项通过**。
  产品实现未改；原始 CI 失败保留，须查看修正提交后的 CI。

本机证据位于构建根 `artifacts/uart-baud-host-20261106/`，常规检查日志位于
`reports/`。浏览器截图为 `uart-10m-browser.png`，查询证据为 `browser-queries.json`。
浏览器夹具禁止构造串口并替换探针查询，不访问物理设备。

本轮没有修改串口收发循环、MUX、RTT、SuperWatch、DAP 调度或采样解析；
离线检查不构成硬件吞吐、长稳或安装资格。指定固件会话报告 V3/V4 的
34 档物理回环与逻辑分析仪测量均通过；最终固件候选、长测和目标回归以
固件仓库报告为准，不把普通 UART 的结论外推到 RS485。
