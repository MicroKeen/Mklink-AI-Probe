# V0.5.0 安装路径、脱机刷新和工程日志修复

日期：2026-11-15。版本保持 0.5.0；先本机覆盖，配合固件会话完成验收，再更新腾讯云。

## 原因与改动

- 0.4.3 使用 NSIS `perMachine`，0.5.0 改为 `currentUser`。Tauri 默认只在当前
  安装上下文恢复目录，旧 HKLM 目录未被采用；更新器没有传 `/D`，可能在用户默认
  目录安装第二份。`/UPDATE` 又保留旧快捷方式，重新打开旧目录里的 0.4.3 会再次下载。
- 安装器在交互和静默覆盖前读取有效的 HKLM/HKCU 产品目录及卸载登记。已有机器级
  副本时修复原位置，兼容此前误建的用户副本；显式 `/D` 和目录页选择优先。
  NSIS 会从 `$CMDLINE` 去掉 `/D`，因此仅用原始 Windows 命令行判断是否指定覆盖位置。
  修复原路径时重定向指向旧用户副本的桌面、开始菜单和任务栏快捷方式，保留无关快捷方式。
- 仍默认普通用户安装，不修改 HKLM、USB 名称或目录权限。旧受保护目录无法写入时
  明确失败并提示以管理员身份运行覆盖安装器，不静默创建第二份安装。
- 脱机页原本每次三秒轮询都打开“识别中”状态。后台检测现在静默，只有首次进入和
  手动刷新显示忙碌；请求串行，切换设备使旧返回失效，手动刷新可以排队。相同状态不重设。
  USB 身份仍逐次核验，不打开 CDC；只缓存 U 盘展示用版本（成功 30 秒，未读到 3 秒），
  手动刷新强制重读，设备丢失清缓存；部署仍独立校验身份，不凭展示缓存选择设备。
- 原 Skill 已要求工程 `.mklink/` 保存脚本/日志/报告，但记录器没有拒绝安装目录。
  补充首次连接显式 `project_root`、复用后台核对工程、记录目录显式设为项目
  `.mklink/logs/`。RTT、SuperWatch、SystemView、串口/Modbus 文件记录和手动转换
  在写入前拒绝 Skill/桌面安装树，包括目录链接。只检查开始/转换入口，不加到采集热路径。
  已有原始记录不删除或迁移；后台发现注册和限额轮转的服务诊断不属于项目采集文件。

## 验证安排与范围

原发布测试显式传了 `/D`，原生更新测试机又已有有效 HKCU 目录，未覆盖 HKLM-only
这个迁移场景。本轮必须用无 `/D` 的实际 NSIS 覆盖重新验证，不能沿用原结论代替。

专项 NSIS 解析器测试包括旧机器级、重复用户副本、用户级、过期登记、中文/空格目录、
显式 `/D`、目录页选择和新装默认值。使用隔离注册表命名空间，不更改真实机器级登记。
专项 234 项在修复 Modbus 路径检查缺少导入后通过；GUI 全量 1294 项及生产构建通过。
首轮 Python 全量 7181 通过/2 跳过，唯一失败是 Skill 正文超过 4500 字符预算；已压缩到
4498 字符且保留原路径约束。最终 Python 全量 **7190 通过、2 跳过**，耗时 1277.93 秒；
GUI 全量 **1294 通过**，生产构建通过。最终运行显式提供已验证的外盘 FLM/Pack 资源；
此前遗漏资源环境的运行出现 21 失败/4 错误，原日志保留，不能作为产品失败或成功证据。
PR #84 的反馈契约、共享 GUI 和共享后台 CI 均通过。
