# HPM GUI acceptance fixes

Development branch only; no release or merge.

- Connection setup now prepares SuperWatch before publishing the session. A
  catalog failure closes the opened device, releases the lease and returns a
  readable HTTP error. Corrected configuration can reconnect without restarting.
  No peripheral catalog definitions changed.
- HPM offline templates omit generic SWD reset/run after ROM programming. ARM
  completion behavior is preserved. V2/V3/V4 generation and HTTP preview covered;
  generation coverage does not certify all probe/target combinations on hardware.
- SystemView accepts the single optional space left by the firmware `>>> `
  prompt before SV, including fragmented USB input. Other prefixes still fail
  with a bounded diagnostic; event payload whitespace is preserved.
- Standalone array snapshots show element indices and the element count rather
  than an empty time-history count. Mixed array/time plots retain their existing
  layout; this is not a shared index/time coordinate redesign.

Validation: 172 API/target/online-probe tests; 159 offline/peripheral/SuperWatch
stream tests; 149 SystemView tests; 95 WaveformViewer tests and production GUI
build passed. GUI deployment and live follow-up are coordinated with the docs
acceptance task. Native CSV/PNG save dialogs are unavailable to its browser-only
control surface; actual file saving remains unverified.

Live SystemView diagnostic after the host patch starts with ten zero sync bytes
and event data, not SV. Both CLI and GUI use Device.systemview_start and the same
Recorder session. Firmware inspection found Recorder state was initialized only
at boot and not reset by start/stop/uninit. A separate probe patch resets it at
these boundaries; hardware retest is pending. Do not claim the optional prompt
space correction alone fixed this observed failure.
