# 0.2.2 V4 narrow-read and shared-stream verification

MicroLink V4 with STM32F103RET6; GUI and AI subscribed to the same backend. Each capture lasted 30 seconds. These are multi-channel validation counts, not single-variable peak sampling rates.

| MHz | Static samples (8 channels) | Dynamic samples (6 channels) |
| --- | ---: | ---: |
| 10 | 354846 | 3387911 |
| 20 | 523634 | 3316481 |
| 30 | 621770 | 3322689 |

Static checks covered four byte lanes, aligned halfwords, halfwords at odd offsets 1 and 3 (including a word boundary). Dynamic checks covered alternating u8 and aligned u16 values, including the halfword at offset 2. All recorded values matched; sequence gaps, invalid timestamps, CRC errors and firmware drop flags were zero. Odd-address dynamic reads are not claimed atomic.

The legacy WebSocket implementation reproduced an AssertionError in concurrent heartbeat/drain handling. All three server startup paths now select websockets-sansio, requiring uvicorn >= 0.35. The final three dynamic captures completed with no such server error. Keepalive remains enabled. Targeted Python regression: 223 passed. Earlier GUI regression: 706 passed, including draggable paths.

The intrusive RAM test harness timed out during bulk cleanup even after successful captures. Changed bytes were restored manually and the MCU was reset/resumed; system tick advanced afterward. Thus capture assertions passed, but the whole harness did not exit successfully. No claim is made that all USB recovery scenarios are resolved. The customer ELF was unavailable and the customer's original glitch was not independently reproduced.

Local raw evidence is retained under the ignored build reports directory; no device identifiers or hardware binaries are committed. Offline installer qualification is recorded separately.
