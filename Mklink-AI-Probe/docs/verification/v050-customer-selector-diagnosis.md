2026-11-13，针对后续截图及对应诊断 ZIP 做只读分析。与此前 [jobs.json 权限诊断](v050-customer-journal-diagnosis.md) 分开记录；不将不同客户或不同版本的证据合并。原始日志、账户路径及设备标识不入库。

## 包内事实

- manifest 标记 **Windows 11 / AMD64 / 0.3.6**，生成时间为 2026-11-13 19:16:51 +08:00。截图“正在下载 v0.4.3”表示更新下载状态，不能据此认定已经运行 0.4.3。包内未提供可核对的构建提交。
- 当日三个后台共记录 **44 次** `/api/runtime/select` 失败，异常链为 `Cannot read job journal; preserve it for inspection` → `UnicodeDecodeError`，首字节 `0x89` 不是有效 UTF-8 起始字节。这是任务记录内容/编码问题，与前一份包的 `PermissionError` 不同。
- 其后两轮均成功打开 COM16，并进入 `connection.ready`；打开耗时分别 672 ms、732 ms。因此不能说该端口从未识别成功。

| --- | --- | --- |
| 连接就绪 | 19:10:15.379 | 19:14:06.417 |
| 串口读失败 | 19:10:47.868 | 19:14:31.663 |
| 恢复时无法唯一匹配原下载器 | 19:10:48.128 | 19:14:31.800 |
| 自动恢复到期 | 19:10:53.235 | 19:14:36.913 |

两次传输失败均为 `CDC queued read failed (WinError 995: 由于线程退出或应用程序请求，已中止 I/O 操作。)`，来源是 `serial_reader`，失败时连接状态为 READY。恢复事件中 `streams` 为空，没有记录正在恢复的采集流。

自动恢复等待约 5 秒，实际重新打开次数为 0；枚举阶段已无法唯一匹配，因而没有盲目重开串口。第二轮失败后又有 **19 次** `/api/runtime/select` 返回截图中的 `Probe selector is missing or ambiguous; run mklink probes list`。

## 源码对应及判断边界

对照官方 `v0.3.6` 和当前 `0b60cda0`：

- `mklink/probes.py::select_probe()` 对零匹配和多匹配使用同一个错误。`recovery.probe_unavailable` 不足以区分二者；包内没有故障时完整端口/USB 枚举列表。画面仍显示 COM16 和标识，也不代表当时实时枚举成功，因为 GUI 列表来自上次刷新结果。
- `mklink/runtime_recovery.py` 在重新打开前核对原身份，枚举不匹配时只等待，不自动改连其他设备。日志中的 `attempts=0` 与该路径一致。
- `mklink/_serial_worker.py` 在异步读取失败且不属于已标记关闭的取消路径时报告 WinError 995。错误说明读取被中止，不能单凭它认定物理拔线、固件复位、Windows 驱动异常或应用取消的具体来源。
- 当前 `RuntimeJobs._restore()` 已对 `PermissionError` 做历史未知保护，但 `UnicodeError`、非法 JSON 等仍抛出异常阻止选择设备。**现有 V0.5.0 候选不能保证修复这份包中的任务记录内容问题。**

诊断包不含原 `jobs.json` 内容/路径、故障时完整 USB 枚举、固件版本及系统设备事件。无法判断首字节来自何种文件、是谁写入、两轮是否读取同一记录文件，也无法证明任务文件错误导致后续 USB 传输中止。历史 COM10 事件不能证明本次 COM16 在故障时发生了端口重分配。

## 建议后续处理

1. 先保留异常任务记录，完善非 UTF-8/非法 JSON 的连接降级处理：允许无关连接流程继续，依赖历史的操作仍明确阻止，避免丢弃未决任务、覆盖原记录或自动重放未知结果。具体恢复/备份策略需实现后验证，不能让用户直接删除整个 runtime 目录。
2. 将零匹配、多匹配区分为可操作的中文/英文提示；设备丢失后刷新列表，仍要求用户明确选择，不自动切换其他下载器。补充脱敏的枚举计数/匹配结果，便于下一轮定位。
3. 客户排查先确认客户端更新完成并退出旧后台；重新插入下载器后刷新、重新选择命令端口。如果仍复现，收集同一轮的新诊断、固件版本和 Windows 设备枚举/事件。更新客户端或固件本身不构成本例已修复的证据。
