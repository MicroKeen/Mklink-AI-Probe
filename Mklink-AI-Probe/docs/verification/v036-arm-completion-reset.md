# ARM 脱机每板完成动作

功能源 eca8b0b0；生产 Web 7c5dea72。

- ARM 保留下载完成复位开关，增加软件、硬件、断电复位选择。断电恢复电压为 1.8/3.3/5V，触发时确认所选电压；断电间隔沿用在线方式的3秒。
- 每轮全部镜像、选项字、安全配置成功后执行一次完成复位，确认连接稳定后才蜂鸣并报告单板完成。批次结束不重复复位或蜂鸣。编程算法各文件的准备复位仍存在，不能据此宣称全过程只有一次复位。
- 蜂鸣继续复用 cmd.set_beep_on / time.sleep_ms / cmd.set_beep_off。
- 新 ARM 配置先检查 cmd.reset_target(0)=-1，再使用软件1/硬件2的检查型复位接口；失败立即停止，不调用第二次cpu_run，不重复复位。
- 新 ARM 配置使用只读实时 cmd.read_swd_idcode；不使用后台缓存判断换板。成功后先2次有效样本，再要求3次无响应、100ms间隔（跨度至少200ms）确认移除。负值表示忙/取消/错误，不能当作拔板；不会启动下一轮。
- UI 超时改为“目标连接／换板等待时间（ms）”；payload字段保留以兼容旧客户端。省略reset_mode的旧payload保留原复位接口；HPM继续原ROM内部复位，不加入ARM通用复位。
- 单板日志使用board download OK，只有整批正常结束才输出auto download finished，避免部分成功被主机判定整批成功。

验证：305相关Python、51离线GUI及TS/Vite通过。覆盖3板多镜像完成次数、V2单板、复位/写入/供电失败、禁用完成动作、能力预检、负值查询、复位后目标丢失、无效电压、掉线抖动和部分成功不算整批完成。

IAB生产Web+真实API+临时SD/模拟桥验证STM32F103RE双BIN、3轮、100ms、硬件模式预览部署触发；各轮2次BIN后1次复位和1次蜂鸣。切换断电后旧部署失效，电压选择显示，输出与预览对齐，无控制台错误。随后加入实时读/去抖，单元执行再次通过；未把模拟当作物理验收。截图与模拟证据只在本地构建reports/arm-completion-browser。

最终实时读/去抖版本再次在IAB和真实API中模拟3轮：3次镜像写入、3次软件完成复位、3次100ms蜂鸣；中间短暂无响应没有多启动一轮。没有控制台错误。此模拟没有访问物理设备。
