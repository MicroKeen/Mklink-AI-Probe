# SuperWatch 与 RTT 最高速率复测 — 2026-11-03

本轮在同一普通 V4＋STM32H743、30 MHz 配置下对照正式 0.4.2 SDK、当前
`58d3853e` 源码、正式可执行程序及历史固定 SDK。未观察到稳定、单向的新增
SuperWatch/RTT 性能退化，但不能据此宣称所有负载完全零变化。
**历史 HPMLink 的约 808 KiB/s 本轮没有复现，差距仍未闭环。**

## 条件与历史证据

- 当前探针是普通 V4，查询返回 V4.7.2、WATCH_TIMING=2；H743 的 Flash 全部
  223048 字节先在 10 MHz 下逐字节匹配当前 AXF，再进行测试。每轮重新核对
  USB 身份、串口及运行时占用；测试时只有该轮后台持有设备。
- 采样使用 30 MHz 配置及协议确认。本轮没有逻辑分析仪测量，不把配置确认
  当作新的物理 SWCLK 波形证据。没有升级/降级固件、烧写目标或改动产品代码。
- 用户提供的 HPMLink `after-rtt.json` 为约 807.86/807.69 KiB/s，`after-speed`
  及重复报告为约 26.4 万组/s。该报告使用另一产品 HPMLink 和历史固件构建。
  历史 AXF 与当前 AXF 不仅文件指纹不同，其 Flash 段哈希也不同；不能忽略这些
  条件差异直接将 808 KiB/s 作为本轮同条件基线。
- 普通 V4 的 `watch-block-reference-20261030/results.json` 在 30 MHz 下，
  4 字节持续采样三轮为 269669/267797/268755 组/s；10 MHz 下为约 14.9 万组/s。
  前一轮宿主延迟报告的约 14.5 万次/s使用 **10 MHz、4 µs 正周期**，不代表
  30 MHz 的绝对最快模式，见[前轮报告](v043-tail-latency.md)。

为隔离当前宿主改动，先按 A-B-B-A 顺序运行正式 SDK、当前源码、当前源码、
正式 SDK，使用相同 Python 3.14.5、设备、目标程序、采集参数及测试脚本。
之后运行本机正式 0.4.2 可执行程序交叉验证，再运行历史固定 SDK—当前源码—
历史固定 SDK。旧代码只从保留的目录加载，没有覆盖安装或全局 Skill。

## SuperWatch：区分快速短采样、持续采样与仪表盘入口

最快模式沿用旧报告的公共 `capture_dump` 入口，显式传
`fastest=True, period=0`，核对 START 接受周期为 0。它使用与 SuperWatch 相同
的 MUX Watch 采样通道；**不等于普通仪表盘支持周期 0**。每轮每个大小采集
10000 组，逐一核对完整原始字节、样本编号、递增目标时间戳及错误计数。
每个版本有两个会话，每会话各做三轮。

| 连续区域大小 | 正式 SDK 六轮均值，组/s | 当前源码六轮均值，组/s | 变化 |
| ---: | ---: | ---: | ---: |
| 4 B | 263508.13 | 264770.48 | +0.48% |
| 16 B | 26571.55 | 26529.82 | -0.16% |
| 64 B | 12904.58 | 12898.65 | -0.05% |

当前源码 4 B 六轮范围为 **261808.76～266072.38 组/s**。每组只有一个
4 字节变量，因此该项也是变量值/s；16/64 B 的组率不能当作每个变量的独立
API 调用率。10000 组的 4 B 短窗口约 38 ms，不能单独用它证明长期持续吞吐。

持续测试沿用旧普通 V4 报告的 `measure_dump_memory`，请求周期 1 µs，每轮
5 秒，保留 200 ms 目标时间戳预热；每版四轮。此处 1 µs 是请求值，不代表
实际能够 1 MHz 采样。

| 指标 | 正式 SDK | 当前源码 |
| --- | ---: | ---: |
| 持续 4 B 平均组/s | 260806.96 | **259782.42** |
| 四轮范围，组/s | 260318～261606 | 259265～260329 |

持续均值差为 -0.39%。统计使用完整样本的目标时间戳，核对 CRC、帧/字节丢弃、
固件读错及丢样标志；该汇总接口不保存每个原始值，完整值验证由上面的有限
采样及下面的真实仪表盘二进制订阅完成。正式可执行程序的持续均值为
259944.89 组/s，与候选处于同一水平。

普通 SuperWatch 入口仍保持最低 **4 µs** 周期。单个 `memory_test[0]`、
30 MHz、15 秒稳定窗口，并实际订阅二进制流逐行验证数值和帧序号：

| 宿主 | read_cycles/s | 收到数据的目标时间戳速率，组/s | 完整值验证行数 |
| --- | ---: | ---: | ---: |
| 正式 SDK | 227483.07 | 227124.45 | 3651250 |
| 当前源码 | **228666.62** | 228451.50 | 3662807 |
| 正式可执行程序 | 228426.87 | 228017.44 | 3663315 |

这解释了两种速度：最快模式约 **26.5 万组/s**，正常仪表盘最低周期入口约
**22.9 万次/s**。它们都不表示单次 SDK 往返耗时；通用读取的 P95 问题仍开放。
全部 10977372 行数值正确，无序号缺口、读错或报告的丢弃。

## RTT：完整 10 MiB 传输，不只挑最好一次

条件为 CH1、16 KiB 目标环形缓冲、480 B MUX 量子，目标写块分别为
1024/2048 B，每项传输 10 MiB。主机计时从发送生产请求前开始，到收到完整
数据结束，包含触发/首包开销；另记录目标周期计时。每一块的序号和全部
载荷字节均验证，并保存原始数据及 SHA256。

| 顺序 / 宿主 | 1024 B 块，KiB/s | 2048 B 块，KiB/s |
| --- | ---: | ---: |
| A1：正式 SDK | 715.96 | 695.90 |
| B1：当前源码 | 652.20 | 688.15 |
| B2：当前源码 | 696.25 | 652.28 |
| A2：正式 SDK | 651.64 | 651.91 |
| 正式可执行程序 | 652.55 | 668.32 |
| 历史固定 SDK | 725.62 | 736.54 |
| 紧邻当前源码复测 | **726.34** | **737.25** |
| 历史固定 SDK 重复 | 695.76 | 686.06 |

预先安排的 A-B-B-A 四次传输均值：正式 SDK **678.86 KiB/s**，当前源码
**672.22 KiB/s**，相差 -0.98%；轮间波动明显大于该均值差。追加紧邻对照后，
当前源码最高单轮完整传输速率为 **737.25 KiB/s**，六次范围
652.20～737.25 KiB/s、均值 692.08 KiB/s。历史固定 SDK 也未在当前设备和目标
程序下恢复 808 KiB/s；旧—新—旧结果没有呈现稳定、单向的新代码退化。

不能将本结论扩大为“RTT 与历史完全无退化”或“已经达到硬件极限”。本轮
没有对原 HPMLink、原固件、原目标程序做原条件复验，也没有定位当前约
652～737 KiB/s 波动的全部来源。没有通过升级/降级、刷回目标或删除较慢
轮次来制造可比结果。
