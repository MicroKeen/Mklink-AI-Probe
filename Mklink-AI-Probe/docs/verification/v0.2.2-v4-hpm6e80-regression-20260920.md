## Scope and tested build

HPM6E80 EVK, SDK 1.12.1 hello_world fixture, JTAG logic analyzer connected; UART not connected. This is a bounded regression, not a multi-hour soak or certification of every peripheral. No OTP/security operation was performed.

Probe package: HPMLink.uf2, SHA-256 `09f05fb280f73da15710e85114121c787d891dae08d16d85cb0b70d6870f2cda`. Compiled with SES 8.24 and installed through the UF2 bootloader. Target image: 51,252 bytes at 0x80000400, SHA-256 `2e40e3de6c3750114f58a0f4753c86f21c55887c67d580682d6dd522987c5ae3`. The shared HPM JTAG ID confirms architecture, not exact part identity; HPM6E80 was explicitly supplied.

## Defects fixed

1. **Probe-local unaligned access during HPM RAM writes.** A 7-byte write at an address ending in +1 reproduced a command timeout. After writing the byte head, the old code cast the remaining local byte buffer to `uint32_t*`, whose alignment was no longer guaranteed. Replaced read/write fallback word accesses with byte assembly/disassembly in `riscv_debug_sysbus_write_mem` and the corresponding read path. The new package passed 128 write/read/restore cases across four clock profiles, offsets 0–3 and lengths 1/2/3/4/5/7/16/31. Full 4 KiB fixture comparison confirmed surrounding data remained intact. This explains the reproduced timeout; it does not establish the cause of every historical USB report.
2. **Cortex-M debug commands sent to a RISC-V target.** CPU halt/resume/step, hardware-breakpoint and core-register APIs now reject HPM before target accesses. HardFault and fallback Cortex-M register-name handling also recognize the shared HPM ID when the detected name is empty. This prevents wrong-architecture accesses; it does not implement RISC-V CPU debug control. Direct hardware checks and fresh CLI/MCP processes passed. The existing GUI backend still requires restart before its new guard can be qualified.

49 relevant Python tests passed (debug guards, HardFault, memory completeness, CLI debug control, HPM flash results and project detection).

## Logic analyzer

Three 0.2-second captures at 500 MSa/s contain JTAG activity on TDI/TMS/TCK/TDO. Requested 10 MHz: dominant periods 104–108 ns; requested 20 MHz: 52–54 ns; requested 30 MHz: 32–34 ns. Whole-transaction gaps and TAP-state clocks must not be treated as shift-clock frequency. These observations confirm signal recovery and roughly 30 MHz shifts, but do not establish exact 10/20 MHz calibration; no claim of exact nominal clocks is made.

## Limits and remaining acceptance

UART/physical Modbus are untested because UART is not connected. OTP/security, Keil IDE, remote-site transport, installer update, prolonged USB disconnect/reconnect and multi-hour soak were not performed this round. CPU debug control on HPM is explicitly unsupported rather than marked passed. The refreshed browser still uses a Python backend started before the new host guard; restart and final GUI guard verification remain pending. Prior STM32 evidence is separate and is not substituted for HPM validation.
