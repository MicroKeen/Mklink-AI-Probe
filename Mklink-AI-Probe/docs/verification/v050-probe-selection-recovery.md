# 异常任务记录与多下载器连接修复

2026-11-13，源码及生产 Web 资源提交 `03fe2cfa`，位于 `codex/v0.5.0-fixes` / PR #79。
对应此前 [客户诊断](v050-customer-selector-diagnosis.md)。本轮未重打 NSIS、覆盖安装、升级固件或发布；已安装的 `3a3fb298` 候选仍不含本轮修复。

## 行为变更

- `jobs.json` 非 UTF-8、非法 JSON 或记录结构不完整时，保留原文件并标记历史未知，普通连接可继续。任务查询及依赖历史的操作返回明确 503；无效记录不写回，不自动删除、重放或把未知任务视为成功。
- 验证整个历史后才提交到内存，避免半份有效记录被恢复/写回。文件消失不消除未知状态；恢复有效历史并重新选择其设备后再解除限制。一个窗口切换后的未读约束继续保留，另一个窗口的正常记录独立处理。
- 下载器零匹配、多匹配、未明确选择和被另一后台占用分别返回结构化原因。诊断事件增加脱敏的候选/匹配计数，恢复等待不重复写同一错误事件。
- GUI 明确选择按下载器身份提交，后端解析当前命令口，不用旧 COM 号重新覆盖解析结果。端口复用不改连新设备；原身份重编号后可刷新重连。
- 意外连接丢失会保留原下载器身份；重试不自动改连仅剩的另一设备。用户仍可明确选择新设备。手动“自动搜索”的失效历史 COM 偏好不再阻塞唯一候选，多候选仍要求明确选择。
- 双窗口各自持有后台和物理锁。切换先预留新设备，失败时保留原连接；成功后才释放旧设备。断开释放设备但保留窗口后台。CLI/MCP 复用同一后端约束，Skill 参考文档已同步。

## 两只实物与生产浏览器

用户提供 MicroLink V4 + STM32F103，以及 HPMLink V4 + HPM5301。实际查询分别为 **V4.7.4** 与 **HPMLink V4.7.2**。测试前未发现运行中的 MKLink 后台；使用当前源码、独立临时工程及真实生产资源，每个窗口一个后台，不修改用户工程。

1. 两窗口分别连接成功，STM32 窗口识别 STM32F10x，HPM 窗口使用 JTAG。HPM 缓存 IDCODE 不作为精确型号或实时 RAM 访问证明；目标型号由用户提供。
2. 在 HPM 窗口选择另一窗口占用的 MicroLink，显示中文占用提示；两窗口原连接保持，未释放原设备或接管他人设备。
3. 第二窗口主动断开后，第一窗口切到 MicroLink，再切回 HPMLink；第一窗口的后台 PID、实例和 HTTP 端口保持不变，目标配置随选择更新。第二窗口可重新连接释放后的 MicroLink。
4. 用户两轮仅拔掉 MicroLink USB，HPMLink 窗口持续连接。最终轮 HPMLink 的 PID、实例及 `device_generation=1` 前后一致；MicroLink 的恢复状态到期后，重试显示明确设备丢失提示，没有改连 HPMLink。
5. 最终轮真实浏览器验证中文/英文丢失提示；MicroLink 插回后按原身份刷新、重连成功，无需重启窗口。
6. 另用 GUI 同一 `new_window` 后台入口补测：先连接第一目标，再创建第二个独立后台并连接第二目标，第一目标的连接、身份及代次不变。此项是后端实物验证，前五项包含实际浏览器操作。

初次验收辅助脚本在选择后未同步自身旧 lobby 身份，后续请求被 409 正确拒绝；修正辅助脚本的身份同步后重新执行。没有绕过产品身份检查。

测试结束正常分离测试会话、关闭页面和后台，重新查询运行后台数为零。未刷写、复位或修改供电。HPMLink 旧固件升级提示正常出现，选择稍后，没有执行升级。
