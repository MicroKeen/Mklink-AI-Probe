# SuperWatch high-rate presentation qualification

## Change

At the V2 30 MHz profile, a single 32-bit variable can produce far more
samples than the old per-512-sample WebSocket/UI notification cadence could
comfortably distribute to multiple pages. Previous local evidence recorded
queue saturation at 64 packets and dropped distribution batches.

The default binary batch cap is now 4096 samples. The existing 64 KiB byte
limit and 20 ms latency flush remain in force, including immediate delivery
for slow requested sampling periods. No sample decimation or protocol change
is introduced.

SuperWatch summary/health updates to Vue are coalesced at 33 ms. The Worker
still retains every received sample in its bounded history. Coalescing adds
sample counts rather than replacing them, preserving acquisition-rate
accounting. Reset/configuration/unmount clear pending presentation; stop
flushes the final summary. Other stream types and frame acknowledgements
remain unchanged.

## Validation — 2026-09-18

- Python streaming regression: 83 passed, including a 4096-row payload check
  and existing size/latency/slow-rate cases.
- GUI composable, client and waveform regression: 109 passed. The new case
  checks summary count aggregation, latest sequence, reset, stop and unmount.
- Production Vue/TypeScript/Vite build passed; tracked runtime rebuilt.
- V2 + STM32F103RET6, 30 MHz, one live float, requested interval 1 us,
  two simultaneous browser subscribers. Approximately 65 seconds / 8,910,073
  complete samples: zero parser CRC/frame errors, zero firmware flags, zero
  host distribution dropped batches/items; queue high-water mark 6 of 64.
- Fifteen-second Chrome measurement: 308 distinct rendered envelope updates,
  approximately 20.5 curve updates/s. rAF p99 8.5 ms, maximum 8.6 ms,
  no browser long tasks over 50 ms. This measures the tested page and workload,
  not all devices or operating conditions.
- Live curve screenshot and stop/start interaction verified. Screenshot
  reported about 150 kSa/s; backend status snapshots varied around 135–138
  kSa/s. These UI/host rates are not the independent firmware-only 188 kSa/s
  measurement and are not advertised as such.

Local raw evidence is under the ignored build reports directory, prefixed
`gui30-`. Hardware identifiers, screenshots and local paths are not published.
No firmware change, installer release or main-branch merge is part of this fix.
