# 0.3.6 桌面启动优化与诊断入口调整

源码：`60bcc8df644103086211365193a8bf6b801e6b39`。本地 Windows preview 候选，未正式发布。

## 修改与原因

- “导出诊断包”从全局页脚移至“配置 → 后台管理”的顶部操作区。没有设备、后台状态读取失败或后台已退出时仍保留入口；远程访客继续不提供本机日志导出。
- 原 Windows 安装包使用 PyInstaller onefile。桌面代理与独立共享后台各自解压完整 Python、FLM 和 Pack 载荷，且后台必须独立于启动者存活，不能复用启动者的临时解压目录。
- Windows 改为 onedir，由 NSIS 一次性安装完整 `_internal` 依赖，两个进程直接读取安装目录。保留完整离线资源、原有窗口/后台所有权、超时预算和安装文件占用保护。没有以复用临时目录、延迟校验或移除算法换取速度。
- Tauri 当前资源路径归一化会丢弃 Windows 盘符，首次跨盘绝对路径打包失败。改为仅打包期间创建独有相对资源目录并在退出时清理，编译/缓存仍在统一 F 盘构建空间；再次构建成功。

## 实测

同一电脑、Windows-only PATH、每次创建独立无设备后台，从启动桌面代理到 `/api/health` 成功：

| 安装结构 | 第一次 | 第二次 | 第三次 | 中位数 |
| --- | ---: | ---: | ---: | ---: |
| 旧版已安装 onefile | 9.688 s | 9.765 s | 15.850 s | 9.765 s |
| 新包解压后 onedir | 1.629 s | 1.553 s | 1.530 s | 1.553 s |
| 新包覆盖安装后 onedir | 1.578 s | 1.498 s | 1.491 s | 1.498 s |

新包覆盖安装后在上述同机测试中缩短约 85%。这是后台就绪时间，不是所有客户电脑的完整窗口显示时间；未通过重启 Windows 清除文件缓存。

## 第二轮：真实阶段与分段计时

用户要求继续优化、重新打包实装。基于上述 onedir 版本进行；本节不把源码计时当作实装结果。

通过 `MKLINK_STARTUP_TIMING=1` 记录 Python 固定阶段的单调时钟，原生可记录导航内阶段及进程启动以来的工作区就绪耗时。默认不写性能采样文件；采样只含固定阶段、时间与本地进程号，不含路径、设备身份或凭证。

优化前同机源码三次代理到健康为 1.985、1.886、1.904 秒，中位数 1.904 秒。第二次的分段观察：

| 工作 | 耗时 |
| --- | ---: |
| 代理 CLI 导入与解析 | 66 ms |
| 代理服务依赖导入 | 291 ms |
| 仅为端点工具而导入完整设备 API | 53 ms |
| 独立后台入口到服务初始化 | 104 ms |
| 独立后台依赖导入 | 279 ms |
| 独立后台设备 API 注册 | 279 ms |
| 独立后台控制接口注册 | 67 ms |

这些是两个进程内部的区间，不能简单相加作为窗口首屏时间。其余时间包括 Python 进程装载、后台发现、网络服务 lifespan 与采样轮询。

- 未指定设备且允许未连接后台的新窗口直接进入 lobby，避免此前枚举 USB 后又丢弃选择；显式设备选择和禁止 lobby 的路径保持身份检查。
- 端点绑定/原子写入拆到轻量模块，代理不再仅为这两个函数加载完整设备 API。原导入位置保留兼容别名。
- 已启动子进程的发现轮询由 200 ms 缩到 50 ms；超时预算、故障退出检查、端口保留和进程所有权不变。
- 前端代码加载与后台地址初始化并行，页面挂载仍等待地址初始化完成；等首路由和两帧后结束启动画面。后台失败可进入恢复页面，界面加载失败显示重试入口。
- 三个阶段分别反映“建立本地服务连接、加载界面模块、显示工作区”，不再按时间虚增百分比。

上述改动后同机源码三次为 1.759、1.693、1.685 秒，中位数 1.693 秒，约减少 11%。新安装包结果待实装补录。证据目录：`F:/MKLink-Build/artifacts/v036-startup-stages-20261024`。
