# S32K344 在线烧录

Windows 0.5.2 客户验证修订。桌面与 Web 使用同一在线作业接口 `POST /api/online-flash/jobs`。

## 使用

- 正常下载按已检查镜像覆盖的扇区擦写。目标运行 RTOS 时，在作业中勾选复位并选择软件复位。遇到持续中断或不适合执行 FLM 的线程栈时，后台可在首次擦写前执行一次所选复位，在同一 MEM-AP 上重新核对型号、复位向量捕获、Thumb 和特权 Thread/MSP。作业末尾的复位仍按用户选择执行。
- 单独擦除算法覆盖区时，在在线烧录页选择一个供应商 FLM，点“擦除算法范围”，核对确认框中的算法名和首尾地址。后台核对 FLM 文件和 FlashDevice 扇区表，再按实物内存映射逐扇区擦除。读回和按镜像范围擦除分别使用原有入口。
- 自动化调用使用一个 `algorithm_ids`、独立的擦除作业和 `algorithm_erase_range: [start, end)`（请求中的数组是两个整数，结束地址不包含在内）。`flash_prepare_reset: true` 允许仅在擦除准备需要时使用所选的 default、software、system 或 hardware 复位。S32K344 Code 范围为 `[0x00400000, 0x007E0000)`。确认这个范围将擦除启动程序。
- 冷上电后，S32K344 的部分系统 SRAM 可能尚未建立 ECC。后台检查已选厂商 FLM 的代码、栈、静态区及页缓冲，仅在明确擦写时，对其已授权工作区内出现总线访问错误的块做 64 位初始化并读回。应用已占用 eDMA 时停止。复位或 DMA 启动应答丢失时保留失败，避免重复发令。

## 实板

固件会话在用户冷上电的 S32K344 上，通过生产在线作业 API 验证。初始 AP4 工作 RAM 读取报 FAULT，目标在 IRQ87，IPSR=103、CONTROL=4。10 MHz SWD，局部擦除、写入 1,592 字节、校验、软件复位及断开全部成功，用时 1.845 秒。新建会话逐字节复核 0x00602000 的整个 8 KiB 扇区，启动区和相邻两个扇区与原快照一致，复位后目标运行，VTOR=0x00400800。

对整段 Code 空间，实板预检确认 496 个 8 KiB 扇区，首地址 0x00400000、末扇区起点 0x007DE000。预检拦截了最终擦除调用，物理擦除覆盖仅限上述局部扇区。模型另外验证了错误 FLM、越界、末扇区几何缺失和未知复位结果。

## Windows 客户包

源码 `e2c7b6e8`，Windows x64 NSIS，0.5.2，188,287,807 字节，未签名。SHA-256 为 `83351d7829f8abff408b108d32b188ee6269a0837aa98b5f8d60b1962517eca4`。

449 项 Python 回归和 129 项在线烧录界面回归通过。覆盖安装退出码为 0，原设置和快捷方式保留，3,761 个随包文件与安装目录逐项一致。原生桌面和随包后台启动、探针枚举、MCP 和正常退出通过。在 Edge 打开安装版服务，选择 S32K344 内置 Code FLM，确认框显示 0x00400000–0x007DFFFF，取消后没有创建作业。使用安装包内 Python 代码和 FLM 的隔离测试中，无界或超范围返回 422，准确范围返回 200，已拦截物理执行。
