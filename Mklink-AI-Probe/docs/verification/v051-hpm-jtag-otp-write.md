# HPM JTAG 用户 OTP 写入与本地安装验收

2026-11-19。上位机保持 V0.5.0。通用协议对接实现为 `e2d89cf9`，桌面和 Web 资源为 `e7d1c57a`，各系列的上位机配置和单次确认更新为 `c4b250f3`。

## 主机与固件分工

HPMLink V4.7.5 开发固件提供可查询的 OTP ROM v1 接口。型号、预期芯片标识、寄存器、ROM 窗口、用户字、可写位、暂存 RAM 和电压由上位机提供。固件使用目标 ROM 的单 Word 编程调用，核对电压、熔丝原值、访问锁、返回状态和物理回读。上位机独立回读。新接口的预览凭据绑定探针、连接代次、UID、配置及具体位变化，60 秒有效，仅可提交一次。

HPM6E00 用户手册 Rev 0.4 PDF 第 283 页确认 Word 69–79 可存应用数据。HPM6E00 数据手册 Rev 0.6 PDF 第 106、108 页列出 DCDC_IN、VPMC 和 3.3 V I/O 供电的范围。HPM6E80 参考板的 Word 64 及 OTP ROM 驱动版本已读出，并与上位机固定配置核对。暂存区域、系统总线别名、OTP 和 PCFG 地址及程序入口 ABI 按 [HPM SDK 1.13.0](https://github.com/hpmicro/hpm_sdk/tree/v1.13.0/soc/HPM6E00) 核对。用户确认板卡可以复位、从 Flash 启动，JTAG 参考电压接实际 3.3 V 目标电源。

HPM51、53、5E、62、63、64、67、68、6E、6P 共用线协议。每个系列的 OTP 基址、hart 0 ILM 总线地址、可用空间及 PCFG 寄存器由 SDK 几何配置限定。内置 HPM6E80 配置适用于对应芯片标识与 ROM 版本。其余型号可装载维护者独立核对的板卡配置，操作见 [探针工作流](../../references/probe-workflows.md)。无匹配配置时可继续读取。HPM5301 保留旧的用户区及组锁接口。软件回归按十个系列覆盖配置选择、地址生成、越界拒绝、错误响应、一次性凭据与连接隔离。

## 本机验收

- 含写入入口的安装包已覆盖到原 D 盘目录。拆包与已安装桌面程序、冻结 Python 后台逐一比对 SHA-256。用窗口的实际控件进入脱机 OTP 页并刷新，读出 HPM6E80 全部 128 个熔丝值和 128 个影子值。此前独立逐字回读及 CSV 对照见 [全系列读取验收](v051-hpm-jtag-otp.md)。
- 旧 HPMLink V4.7.4 对同一 Word 的预检返回 HTTP 422，明确说明缺少 OTP ROM v1。经用户授权，已对唯一选定的 HPMLink 安装 V4.7.5 测试固件。UF2 SHA-256 为 `b7f1237659ee8971e738d25c1f00ba11f45fd6eda14230dc2482a4c0d028fd59`，Family ID 为 `0x0B4D5048`，重新枚举后读取到的编译时间为 2026-11-19 14:36:54。新固件的只读预检通过，返回原值 0、目标值 1、VREF 3226 mV。
- 使用 F 盘构建根完成 445 项 Python 和 85 项 GUI 回归、TypeScript 检查及本地 NSIS 构建。真实写入授权仅限该 HPM6E80 的应用数据 Word 72 bit 0。其他系列不计为实板验收。公开渠道沿用已发布版本。

## 单次提交与回读

用于首次实测的安装包 SHA-256 为 `4f6b7d97ef0ad6bb1995cb685b54a21ea1e8538b337a31223083198b53d1f58a`。在安装后的共享后台确认同一探针和芯片 UID，Word 72 的物理值与影子均为 0，未锁定。预检电压为 3227 mV。实际仅提交一次从 0 到 1 的变更。固件返回 `rc=-10, issued=1`，表示 ROM 执行请求已经发出，恢复执行或返回状态未获确认。

随后只读核对同一芯片。完整快照中 Word 72 物理值和影子均为 0，独立读取相应的 4 字节物理熔丝也为 0，锁状态未变。写入验收未通过，单次授权已用，没有重发。桌面重新刷新后仍可读取。该候选包适用于本轮桌面读取验收，HPM6E80 的生产写入仍待固件修复和实板闭环。

首次实测后，上位机修订 `66ae9398` 将已发出请求的未知结果与预检拒绝分开显示，按固件有效位保留物理回读和 ROM 状态。Python 回归 446 项通过。同版本 NSIS 的 SHA-256 为 `9c9540c5bf0bb67873800352f023c01ba0f3b869bbfd1247570a7025dd883d6f`，已覆盖安装，两个已安装可执行文件与拆包逐一比对通过。桌面重新读取成功。用户随后明确暂停永久写入，仅进行无熔丝编程的 ROM 诊断。

## HPM6E80 无熔丝编程诊断

同一 HPMLink 已更新到 V4.7.5 开发构建 2026-11-19 15:00:56。其 UF2 SHA-256 为 `6c96ea7b0852fca95498aab91ef0dde670e3b542fa0ad522e684c5869fea9a22`。更新前核对了固件类型、包内容、板卡身份和 Word 72 的原值，更新后重新枚举并核对构建标记。固件侧完成了 534 项离线检查及厂商 SDK 读取函数的 RV32 模拟验证。

实板以 `otp_rom_probe` 调用 ROM 的 `read_from_ip(CHIP_WORD)`。该诊断复用复位、停机、暂存 RAM 和返回断点流程，调用期间固件使用 4 MHz JTAG。只读入口为 `0x20002BA8`，返回 `rc=0, call_rc=0, phase=13`。停机原因是 EBREAK（DCSR cause 1），PC 为预期的 `0x0003F000`，a0 为芯片标识 `0x10206141`，与物理寄存器独立读值一致。外部晶振状态寄存器在复位前与 ROM 调用前均读到 `0x300464FF`，使能及响应位置位，BUSY 为 0。

诊断后再次读取同一块板，Word 72 的物理熔丝、影子和独立四字节回读均为 0，写保护关闭。全程没有调用 OTP PROGRAM。结果确认本次测试固件的 ROM 读调用与返回链路正常，旧固件首次编程失败的具体阶段仍无现场证据。永久写入按用户要求暂停。

## 安装版 MCP 桌面验收

最终本地安装包对应上位机提交 `77791d86`，版本 V0.5.0，SHA-256 为 `f699927900f225b8677a1dca9ebcf70c084045d1eb90ad7d2d9bd5ef6f66963c`。安装到原目录后，桌面程序和后台程序的哈希均与该 NSIS 中的文件一致，已有设置文件校验通过。全量 GUI 测试 114 个文件、1303 项通过，Python 的 OTP、设备配置和共享 GUI 相关回归 319 项通过。另一次较早候选的 446 项回归见上文。

覆盖安装结束了旧的 MCP 连接。验收使用安装目录内的 `mklink-sidecar.exe mcp` 新建 stdio 会话，复用已打开的桌面窗口与共享后台。使用 `gui_control` 打开脱机 OTP 读视图并点击刷新。逐个选中 Word 0–127，通过选中控件的 `description` 获取当前屏幕上的值，核对了全部 128 个熔丝、128 个影子值及各字锁状态。与同一探针上的完整配置读取逐项一致。该显示接口也供 UART ISP 读视图使用，选中单元格不会触发硬件访问。

最后选中 Word 72，界面显示物理值和影子值均为 `0x00000000`，写保护关闭。共享后台的独立四字节回读一致，验证前后为同一板卡，桌面 JTAG 30 MHz 已生效。实板编程仍未验收，其他型号尚待实板验证。此次仅生成本地安装包。
