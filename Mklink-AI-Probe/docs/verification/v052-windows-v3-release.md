2026-11-28。Windows x64 安装包和完整 Skill 的产品构建标识为 `806dbdc8`。源码提交 `6f908307` 包含相应的生产 Web 资源。通过桌面 WebView2 和真实 Edge 打开中英文版本记录，每种语言均显示五条更新，S32K3 占一条。见[用户版本说明](../releases/v0.5.2.md)。

## SuperWatch 与多窗口控制

复现时，主仪表盘通过 `v-show` 保留组件，隐藏后的波形仍持有二进制 WebSocket。共享后台正确识别到这个读者，Skill 的停止请求因此返回 409。修复后，仪表盘与灵活面板把实际可见状态传给波形及独立变量订阅。隐藏时取消窗口的订阅、重连和快照轮询；再次显示时接回同一采集。可见窗口的保护逻辑继续生效。

用候选 NSIS 内的桌面程序和冻结后台、完整 Skill ZIP 内的 stdio MCP、独立 Edge 窗口共用一个 V3.7.1 和一块 STM32F103。实测双采集期间四个 SuperWatch 通道均有新值，原采样间隔为 20 ms。

| 实板操作 | 验收结果 |
| --- | --- |
| 桌面和 Web 同时查看 SuperWatch，Skill 请求停止 | 返回 409，采集继续 |
| 桌面切到配置，仅 Web 查看波形 | 仍返回 409 |
| Web 切到 RTT 后也离开仪表盘 | 后台仍在采样，原 Skill 成功停止 |
| 开第二次采集，桌面重新显示波形，再切到配置 | 可见时请求停止返回 409，隐藏后可正常停止 |
| 记录过程中隐藏波形 | 文件样本计数继续增长，关闭文件后实际解码出 5 个样本，每个样本含 4 个变量 |
| RTT CH1 双向收发与停止 | 下发 6 字节，固件回复计数 17 和哈希 `10822129`，与独立 RAM 读取一致，丢失为 0 |

测试实例通过托盘 Exit 退出。测试使用隔离的候选程序和 Skill 目录，设备 Flash 保持原程序。

## 目标与 Flash 核查

同一 V3 在普通 SWD 上实读 CPUID `0x411FC231`、DBGMCU_IDCODE `0x10036414`、容量 512 KiB、VTOR `0x08005000`。候选 Skill 加载工程 AXF 的 9,105 个变量符号，通过同一后台独立读出全片 524,288 字节。SHA-256 为 `fe7765c9a5242b2d9fd85bd3ba3ff2f9b6c7137211116dac6575109428fe8cc9`。

此前同日，同一台 V3 与已安装的 0.5.2 构建 `3384333a` 完成在线擦写。先用 2 KiB 测试页改动一个字节并读回，再以工程 HEX 写回 119,296 字节、59 页，用时 8.97 秒。前后整片快照与本候选回读三者摘要相同。该次实测另覆盖 2 ms SuperWatch、双采集期间 MCU 复位和断开重连。本次候选的实板范围为 V3 + STM32F103，V3 搭配 S32K3 的冷上电及完整擦写继续列为待验。见[跨系列验证范围](v052-s32k3-family.md)。
