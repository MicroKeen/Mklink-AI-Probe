# V4.7.4 灵活面板长时双窗采集

2026-11-21。旧版为 `ed412d493c3eb8851f45a8b8d97c515cc03c2388`，修复和新增回归为 `5383308ccb0da1deced9677716bc11a8cf1a93e2`。历史观测的 69 批是第一窗口三个 SuperWatch 订阅各缺 23 批。历史健康请求最大值为 1,629 ms。旧记录只保存了延迟汇总和累计丢弃，缺少两者首次出现的共同时间戳。[前轮固件对照](flexible-panel-v474-20261121.md)

## 实物与方法

- 探针自报 MicroLink V4 / V4.7.4。每次新建后台后核对同一块 STM32F411 的芯片身份，并将应用 Flash 段首、中、尾各 16 字节与原 AXF 对照。AXF SHA-256 为 `eed3f3c34c8101d3d25467ba668929ba7e30cd13507304e2d20d14e8e199260e`。SWD 为 10 MHz。板端程序和探针固件沿用前轮。
- 从官方默认生产 Web GUI 打开灵活面板，Playwright 在同一浏览器上下文新建、导航和关闭第二个页面。两个独立页面各有三个 SuperWatch 和两个 RTT worker，包含原仪表盘已挂载的订阅。第一窗口持续显示六个变量的 20 ms 采样和 RTT CH0。
- 每轮待第二个页面挂载完成后双窗观察 16 秒，关闭后再观察第一窗口 5.5 秒。记录浏览器事件时间和每个 worker 的序号、传输间断与主机丢弃。另开客户端约每 140 ms 发起一次健康请求，约每 330 ms 读取流状态与后台 CPU。延迟为本机请求往返时间，百分位按最近秩计算。
- 两版各执行三次 SuperWatch/RTT 同时录制与独立游标读取，三次同通道 RTT 面板新增、暂停、清空和移除，以及 60 次通过真实页面命令执行的布局搜索。下表取首轮打开至末轮关窗观察结束的同一统计口径。操作的实际落点随响应时间变化。

## 定位与对照

旧版在页面上报时同步解码、校验和复制报告。扫描同页命令时，两处循环还会深拷贝已完成回执的结果和状态，用途只是检查其交付状态。旧版完成 60 次布局搜索后，记录到 459 个超过观测阈值的线程栈样本，其中 370 个位于历史回执深拷贝。健康请求 P95 在搜索前、完成搜索后的两个区段分别为 32.17 和 221.49 ms，修复后同口径为 37.49 和 30.56 ms。另一路同步工作位于健康接口本身，需要读取项目配置和 ELF 工具环境。

为区分因果，保持真实板卡和双窗口运行，另在测试进程中对**一次调用**加入 1.75 秒等待。每版分别做两次页面上报校验延时、一次健康接口 ELF 诊断延时。两个独立客户端同时探测健康接口。延时起止、采样计数、队列、两窗 worker 序号和后台线程栈在同一主机时钟下记录。旧版对照启动时有一次 SDK 附着遇到 409，重新附着后开始计时，三轮均完整记录了窗口、健康请求和流遥测。此表为受控延时实验。

| 延时位置 | 旧版健康请求最长 / 新增主机丢弃 | 修复版健康请求最长 / 新增主机丢弃 | 修复版在等待期间完整返回的健康请求数 |
| --- | ---: | ---: | ---: |
| 窗口报告（第一次） | 1,794 ms / 150 | 29 ms / 0 | 22 |
| 健康接口的 ELF 诊断 | 1,773 ms / 150 | 1,768 ms / 0 | 11 |
| 窗口报告（第二次） | 1,726 ms / 162 | 17 ms / 0 | 22 |

旧版三次阻塞均发生在事件循环线程。队列达到 64，六个 SuperWatch 读者每次各缺 25、25、27 批，合计分别为 150、150、162 次投递。此次每个被丢弃的投递只含一个样本，50 Hz 下 64 个单样本批次约对应 1.28 秒。批次合并和元数据会改变这一时间尺度。修复版三次慢处理均在工作线程执行。在 ELF 诊断延时轮，被延迟的请求自身承担该等待，同一阻塞区间内其他健康请求最长 21 ms，采集仍可继续。慢健康请求本身不足以判定丢批。

修复将请求私有的解码和校验交给后台线程，目标身份、页面 revision、回执归属和队列变更仍在所属事件循环内一次提交。历史回执仅在向调用方返回时复制。健康接口使用 FastAPI 同步路由的线程池，保留实时诊断响应及原有字段。订阅队列容量、序号和丢弃计数规则沿用旧版。事件循环长期阻塞可以解释原先两种症状；本轮无法恢复上次现场的具体阻塞调用。

## 自动化回归与范围

新增四项用例在旧版均失败，覆盖慢报告期间的独立健康请求和双订阅分发、校验结束前的目标切换和同页 revision 推进、历史回执的内部复制与对外隔离，以及慢 ELF 诊断期间的第二个健康请求。修复版四项通过。完整受影响测试结果为 16 个后端测试模块，`1147 passed, 4 warnings in 108.56s (0:01:48)`。

在源码目录执行以下命令可重跑聚焦用例。

```powershell
./scripts/build_workspace.ps1 -Action run -Executable python -ArgumentList @(
  '-m','pytest','-q','_maintainer/testing/tests/test_frontend_concurrency.py',
  '_maintainer/testing/tests/test_runtime_frontend.py','_maintainer/testing/tests/test_remote_api.py',
  '-k','slow_exchange or historical_results or slow_elf_diagnostics')
```

受影响模块的复测命令如下。

```powershell
$modules = @(
  'remote_api','runtime_frontend','frontend_concurrency','frontend_storage',
  'frontend_capabilities','frontend_replay','stream_hub','stream_api',
  'rtt_superwatch_streaming','superwatch_recording','superwatch_alignment','desktop_runtime',
  'elf_backend','runtime_idle','shared_runtime','standalone_superwatch_health')
$files = $modules | ForEach-Object { "_maintainer/testing/tests/test_$($_).py" }
./scripts/build_workspace.ps1 -Action run -Executable python -ArgumentList (@('-m','pytest','-q','--tb=short') + $files)
```

本轮实测范围为 Windows 官方 Web GUI、这一块板、六变量 20 ms、RTT CH0 和两个窗口。更高采样率、多探针、原生桌面 WebView 与持续数小时采集不在这次验证范围。
