# 0.4.3 Windows 桌面启动首帧

原版先显示 Tauri 主窗口，WebView2 此时仍在加载内置页面。标志、进度条和样式已随 HTML 内联，Python 后台在另一个线程启动。修复版让 Windows 主窗口在首次应用页面导航完成时显示一次，此后页面重载沿用用户设置的窗口可见状态。

## 两组原生桌面实测

在同一台 Windows 电脑上分别启动旧安装目录与新 NSIS 提取目录中的完整应用。每组三次，第一轮使用独立的新 WebView2 配置，后两轮复用本组配置。以进程启动为时间原点，轮询本进程的主窗口，采集客户区中央。通过启动标志和进度条的两种精确前景色识别首帧，通过中央区域超过 97% 为原窗口底色识别空白帧。截图和处理有采样间隔，因此数字是首次观测值。

| 观测项 | 旧安装版 | 修复候选 |
| --- | --- | --- |
| 主窗口可见至首次识别标志和进度条（ms） | 1424 / 1387 / 1267 | 323 / 312 / 312 |
| 首次识别标志和进度条，距进程启动（ms） | 1477 / 1463 / 1357 | 1609 / 1382 / 1367 |
| 标志出现前采到的纯色空白帧数 | 9 / 8 / 8 | 0 / 0 / 0 |
| 工作区就绪，程序内计时（ms） | 3002 / 2963 / 2982 | 3931 / 2641 / 2825 |

六轮均启动随包后台、显示工作区并正常关闭。独立一轮在实际 WebView2 中隐藏主窗口并重载页面，确认窗口保持隐藏；恢复后导航可用，启动遮罩消失，关闭退出码为 0。此轮观察的是启动画面，完整工作区就绪时间仍受后台初始化影响。

原始逐帧结果、截取的启动图和重载验证位于构建根的 `artifacts/v043-first-frame-20261107` 下，分别见 `original.json`、`candidate.json`、各轮 `frames.json` 和 `reload.json`。本机未签名 NSIS 的 SHA-256 为 `6a00f64cc6094834626dfde81c2380bab3dbcee0981b4e267245d84ca15558d4`。在线烧录的连接选项和睡眠访问行为沿用既有实现。
