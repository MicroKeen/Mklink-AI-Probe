## 日志与新增保护验证

Python 3.12 CI 的无控制台用例失败后，独立进程在 Python 3.12.10 和 3.14 对比
三种缺失 stdout/stderr 的情况，旧实现可复现同一日志再次进入重定向管道、
重复时间戳。日志文件曾在标准描述符预留前打开，占用即将被 dup2 重定向的
描述符。改为延迟打开运行日志，并先建立原生重定向，再打开连接事件日志。
修复后的六组独立进程检查通过。CI 原用例的完整失败条件仍由新头 CI 复验，
不能把本地重现直接等同于原 CI 所有时序。fa653d6b 的反馈合同、共享 GUI 和
共享运行时三个 CI 检查随后全部通过，包含原 Python 3.12 无控制台用例。

新增测试也检查连接日志启停事件、无递归时间戳及原描述符恢复；失败时另存
异常文件，避免 stderr 缺失令报告空白。脱机能力、脚本、API、事务及日志相关
214 项通过。首次新增 V2 夹具误用 3 次自动下载，被现有限制正确拒绝，改为
V2 合法的 1 次后通过，未放宽产品限制。

此前整合运行 5524 Python/2 skip、1104 GUI、生产构建和 15 个 COS 保护用例通过；
新增产品修改后仍需新头完整重跑，旧运行不作为本次最终发布资格。

## 双核在线与脱机分别结论

客户已确认 M7/M4 两份 HEX 在线烧录成功，在线问题按反馈闭环。客户暂时没有
双核板可补验脱机；本机 H743 不能替代双核实物验收。

固件维护确认现有脱机流程缺少双核准备及收尾，已交付候选
V4.7.2/V3.6.8/V2.9.3。上位机为四个已知双核系列生成显式 FLM profile，部署前
要求 OFFLINE_H7_DUALCORE=1，旧固件明确提示升级并拒绝部署；默认校验开启也
不能绕过这个检查。系统/硬件复位检查返回结果，缺省旧调用迁为系统复位；
未请求复位时不恢复核心，电源循环不能替代双核状态确认。普通型号保持原调用。

候选固件未经双核真机验收不替换正式升级索引，不宣称双核脱机已通过。
详见 `h7-dualcore-flash-20261025.md`。

私有 V4.7.2 候选（SHA-256 `5980f49c1257b52bb7942f25d18399ff87eb059c8e605f80b140bff285a6faf8`）
经原探针身份绑定的 UF2 升级路径复制。由于本地候选没有正式目录的构建元数据，
升级器返回 `copied_unverified`；未重放升级。另行核对设备 V4.7.2、构建时间
`2026-10-25T18:59:33` 与候选二进制内时间一致，并确认三项脱机能力标记。
H743 误选 H745、显式 profile=1 时，使用不同于原内容的 HEX，固件在准备编程
时因缺少 CM4/AP3 返回状态 7 并中止。前后独立回读完整 2097152 字节 Flash，
SHA-256 均为 `dc7c9fd5b515c8dae722c4cafc396e8b0fab4928277340b896c980bdf3c46824`。
初始夹具误判拒绝应发生于 FLM 加载，修正为实际编程准备阶段后仅继续只读比较，
没有重放失败任务。此结果只证明单核误选拒绝，不证明双核正常烧录。

候选的普通 H743 回归随后完成：HEX/BIN 校验开关四组合均成功并独立回读
215716 字节，默认校验已恢复开启；在线烧录及 19 项采集/调试检查通过，录制
4070 样本，四组混合采集合计 52847 周期零错误，后台正常退出。当前本机
下载器运行此私有候选，正式固件目录仍为 V4.7.1。
