2026-11-12，任务起点 `85dc447e`，继续 `codex/v0.5.0-fixes` / PR #79。
按用户要求统一 Web GUI、Skill/CLI 和 MCP。没有操作真机、重建安装包或发布。

## 行为与一致性

- 成功加载 `app.axf` / `app.elf` 后，在同目录创建或读取
  `app.axf.superwatch.json` / `app.elf.superwatch.json`。
- 共享后台保存变量名称、常用变量、分组/样式、数组范围、间隔与显示设置。
  按新符号目录重新解析地址；缺失变量保留名称并提示。恢复不会自动采集。
- GUI 自动保存，连续显示/布局编辑合并约 250 ms；CLI/MCP 调用同一组 API。
  CLI 省略 `--period` 沿用配置。MCP 提供 profile、workspace、pins 及保存动作。
- 保存使用节修订与临时文件替换。旧窗口、外部改动、损坏文件、只读目录不会静默覆盖。
  显示与间隔修改在同一配置锁下合并，避免异步提交相互覆盖。
- 配置位于后台持有的符号文件旁。浏览器上传副本不能写回客户端原目录。
  用法、字段和远程边界见[用户参考](../../references/superwatch-profile.md)。

## 性能与未验范围

配置写盘只发生在加载文件或用户修改参数时，使用线程池；不会在样本接收、解码、
绘图刷新或记录回调中写配置。状态轮询读取内存中的配置。GUI 测试确认元数据刷新
不发出持久化事件，101 次连续布局编辑合并一次写入；既有十秒流性能门禁通过。

这不构成新的真机吞吐、P95 或 SWD/RTT/调试共存结论。恢复选项在真实 ELF 重编和
不同 MCU 上的端到端采集、冻结安装包行为留待受影响实物门禁，继续遵守
[0.4.3 上位机基线](v043-host-baseline.md)。本次没有更新已安装候选；合并/发布前仍需
全量 Python、GUI、生产构建与受影响实际环境验证。
