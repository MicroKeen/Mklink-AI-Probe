# 0.4.3 MUX 心跳与采样文件录制修复

2026-11-06，继续 `codex/v0.4.3-fixes`，修改前源为 `838e0c56`。
本轮只验证源码修复，未生成安装包、覆盖安装、刷下载器固件、合并或发布。
用户允许外部调试器占用带宽带来的合理下降；数据正确性、可恢复性和无调试器基线仍须保持。

## 复现与原因

这里的“录制”是 SuperWatch 采样数据 JSONL，区别于诊断日志。旧实现即使
没有额外诊断，也能在持续录制时复现控制请求等待约 39 秒后失败。
带诊断的独立复现等待约 225 秒；串口工作进程积压达到 1024 个包、
2,855,168 字节，输出管道阻塞。堆栈和内存事件记录显示：逐点 JSON 编码
与采集接收共享 Python 执行锁，心跳回复在采样数据之后排队。

另有一个可确定复现的调度问题：延迟约 2 秒的心跳回复释放请求槽位时，
接收线程可抢在已经等待的控制命令之前再次发送心跳。反复发生后控制命令
长期无法发送，最终心跳也超过原有 3 秒截止时间。未延长超时或重放未知结果的写入。

## 实现

- MUX 请求等待槽位时，周期心跳让出下一次发送机会；原截止时间、身份、
  错误及未知结果不重放语义保留。
- 复用 JSON 编码器，沿用原 JSONL、UTF-8、数值精度、时间戳、空隙元数据及分卷规则。
  编码和磁盘写入移至只在录制时启动的专用进程；该进程不导入设备操作入口或打开硬件。
- 父进程队列继续有容量上限，跨进程一次只确认一批。输入管道写入与回复等待分离，
  子进程不读管道、异常退出、写盘失败或超时均明确标记录制不完整，清理进程和线程。
- 子进程启动不持有采集读锁，准备完成后在批边界接入录制。停止仍在采集锁外排空。
  CLI 和桌面冻结入口均增加私有工作进程分派；源码按文件启动不依赖外部 PYTHONPATH。

仅缓存编码器、调整管道容量/批量输出等中间方案未通过持续录制验收，已撤回。
串口工作进程和其管道实现最终没有改动。

## 本地验证

- 定向检查 **193 passed**：MUX 心跳让行、过期请求、文件格式逐字节兼容、中文、
  精度和部分错误、分卷、队列溢出、子进程退出、输入管道卡住及清理、入口分派。
- 扩展相关检查 **787 passed**：MUX、RTT、SuperWatch、共享内存、作业和退出。
  与上述集合有重叠，不能相加当作独立测试数。
- 既有十秒高吞吐流检查 **1 passed**。实际浏览器持续显示，IAR/Keil 原生界面验证。
- IAR C-SPY 真附加/退出 **10 轮**；另有图形界面真附加、暂停、单步、继续、
  菜单退出，附加时校验目标代码 191607 B。Keil 图形界面进出 **5 轮**；
  pyOCD、OpenOCD 暂停、单步、继续、退出各 **5 轮**，每轮核对 4096 B RAM。
  四类调试器分别与 RTT/SuperWatch 并行，不是四个调试器同时争用 CMSIS-DAP。
- 首轮约 **1846 秒**：RTT **65,035,264 B** 全字节验证，其中连续负载
  20503 个块序号连续；**6,666,305** 个录制值及时间戳逐行核对。
  后补有界输入写入后，最终源码重启复验约 **191 秒**，再验证
  **8,714,240 B** RTT 和 **4,642,711** 个采样点，含 IAR 并行录制/控制请求。
  两轮均无心跳超时、CRC/采样错误、接收队列丢弃或 RTT 订阅缺失。
- 最终源码两次九秒录制中的六次已知夹具参数写入均回读正确，六次 4096 B
  读取完整正确；写入约 16–132 ms，读取约 7–77 ms，停止录制约 34–107 ms。
  这些是高负载控制检查，不能当作普通读取的 sub-ms 延迟资格。

目标为同一 STM32H7 IAR 映像，探针仍为 V3 L，采样请求 1 µs，MUX 时钟 30 MHz。
本轮目标源码/映像哈希未改变。IAR 设置 10 MHz 和 30 MHz 均保留证据；不能仅凭
IDE 设置就假定 MUX 采样也降到该频率，保存的采样时钟波形仍约 30 MHz。

### 吞吐与比较窗口

负载为 2 MiB 有限 RTT、4 B SuperWatch、JSONL 录制和实际 Web 页面。
修改前四轮 RTT 为 376.97 / 409.63 / 393.90 / 372.92 KiB/s；
最终源码三轮为 **420.03 / 415.19 / 416.02 KiB/s**。

旧录制期间控制触发延迟，开始约 0.8–1.1 秒仍是没有饱和 RTT 的高速采样，
停止也有延迟；直接比较整份文件平均率会把它误当作新实现采样退化。
保留所有 200 ms 分段统计，并在各次录制开始后的 **1.4–2.0 秒**共同窗口
核对 RTT 持续传输阶段：旧四轮 **116223 / 117101 / 117152 / 116326 samples/s**，
新三轮 **116944 / 116975 / 116954 samples/s**。两组采样间隔 P50/P95/P99
均约 **4/5/16 µs**；新组最大间隔 **1386–1404 µs**，旧组 **1391–4905 µs**。
独立持续录制仍约 23 万 samples/s。此为本映像/负载下的有限同条件对照，
不替换历史独立 RAM 约 26.2 万或独立 RTT 约 854 KiB/s 的另一条件基线。

IAR 并行 RTT 约 **354–357 KiB/s**，最终共同窗口 Watch 约 **9.63 万/s**，
分别较同负载无调试器约低 15% / 18%。数据完整，符合共享调试带宽会产生下降的事实；
未宣称已消除固件调度开销。

## 保留问题和证据边界

**IAR 退出后的会话状态仍是遗留问题。** 命令行进程退出和图形界面菜单退出后，
RTT 仍约 355–356 KiB/s；Keil 正常退出后恢复 **416.04 / 417.69 / 419.44 KiB/s**。
保存的逻辑分析仪边沿经请求/数据奇偶和 ACK 校验，显示 IAR 命令行退出后仍反复
执行调试上下文借用/恢复，与固件 active 状态路径吻合。缺少 USB 退出尾包，
不能断言是 IAR 未发 Disconnect、命令未成功还是后续重开。GUI 有效退出也有
相同吞吐结果，但不能把 CLI 的波形称为 GUI 的波形。

固件会话保留独立的 DAP 等待唤醒源码候选，未构建/刷写；它不解决 active 状态残留。
不得用无命令一段时间就强制清 active 的方式抢走仍有效的调试上下文。
本轮结束已用正常调试会话关闭释放该状态，目标运行，采集停止、设备连接和测试进程释放。

本地证据包 `mux-heartbeat-fix-20261106`：`final-audit.json`、`final2-audit.json`、
`before-after-rates.json`、原始 JSONL/RTT、四种调试器结果和逻辑波形。
固件只读分析包为 `dap-exit-analysis-v3-20261106`，包含独立解码和哈希清单。
完整路径及设备身份保留在本地报告，不上传原始硬件数据。

测试名 `baseline-10m-*` 的在线改频被忙保护 409 拒绝，不能称其为成功的 10 MHz 实验；
`post-iar-gui-*` 实际仍在 GUI 调试中，有效菜单退出后的数据名为 `iar-gui-exited-*`。
原始失败、误名和修正说明均保留。历史最大间隔 20 µs、40 µs 零漏采及普通读
P95/间隔读取稳定小于 1 ms 仍开放；未做本轮冻结安装包资格，不具备正式发布结论。
