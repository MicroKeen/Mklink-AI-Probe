# 固件能力提示与 SuperWatch 写入验证

日期：2026-11-12。开发基线 `b7be4689`，分支 `codex/v0.5.0-fixes`。
本报告属于开发验证，不是正式发布或安装升级验收。

## 结论与实现

同一普通 V4 / STM32F103RC 上，V4.7.3 与 V4.7.4 都已支持 MUX 采集中写入。
本轮没有复现客户截图中的长时间停流。V4.7.4 候选主要修复 SWCLK 中断恢复，
不能将其描述为首次支持 live-write。客户旧上位机和固件组合仍需另行核对。

- 删除 SuperWatch 的 `legacy-gap` 自动停止/写入/重启分支。缺采集中写入能力时
  返回 `firmware_upgrade_required`，保持原采集和暂停状态，不发送写入或 stop/start。
  地址不在允许的 RAM 范围内则提示先显式停止采集，不误报为固件过旧。
- 状态和连接结果提供 `firmware_compatibility`，Web 顶部按需展开缺失能力清单，
  按钮进入固件页面；CLI/SDK/MCP 读取同一后端结果。Skill 和 MCP 工具说明要求转述提醒。
  兼容操作另用 `firmware_warning` 提示；不自动检查更新网络、不刷写、不停止采集。
- 只读已有文本及 HELLO 缓存，不增加采集热路径 USB 查询。版本文本仅识别 V3/V4
  型号，不作为能力门槛。HELLO 未协商时不据此判缺失；V2/未知型号不套用 V3/V4 升级承诺。
- 固件对已知主机命令明确返回 unsupported/status 1 时提示升级；status 2/5/6、
  会话失效、超时、畸形响应、目标/地址限制保持各自原因，未知写入不重放。

`DUMP_WRITE=1` 是历史 DMPM/DMPW 能力，不能单独证明 MUX live-write。
MUX 文本入口为 `MUX_TARGET=1`，HELLO `0x3` 目标命令集已包含 `0x12`；
现代 SuperWatch 另需 `0x618`。固件会话已核对该契约，不以版本字符串替代协商。

## 排查范围

| 功能 | 检查及提示 |
|---|---|
| SuperWatch / 连续内存采集 | MUX 入口、采样 `0x618`、大块 `0x800`；原有缺能力错误保留升级提示，状态补充清单 |
| 采集中写入 | MUX 目标命令集；缺能力预先拒绝，取消隐式停流写入，空闲时仍可显式写入 |
| RTT 多通道 / SystemView | 保留旧单通道限制及增量 RTT `0x80` 提醒；准入和冲突查询补充明确的固件原因 |
| 采集中复位 | `0x20`；任务、Web 和共享准入共用提示；不支持的采集传输仍按传输冲突处理 |
| 内存批量与快速传输 | 4096 字节读 `0x40`、480 字节短传输 `0x100`；较慢兼容能力列入清单 |
| 睡眠访问 | 原子访问 `0x1000`；旧慢速兼容结果提示升级。STOP/目标错误不据此归因于旧固件 |
| SWD/JTAG 时钟 | 已声明档位与 ACK；保留任意频率拒绝、接口和硬件限制，清单提示缺完整时钟契约 |
| 普通 UART | 缺 `UART_BAUD_PROFILE=1` 的已识别 V3/V4 提示升级；普通串口、未知或畸形查询不猜测型号 |
| HPM CPU 调试 / HEX | 补齐 HPM_DEBUG 版本、动作及明确 `-12`，以及 `hpm.program_hex` 缺能力时的升级指引 |
| HPM ISP / UART OTP | 原有 API v1/v2、联合离线任务及系列 profile 升级门槛保留；旧 HPM5301 用户区兼容快照增加三端可见提醒 |
| 脱机校验 / H7 双核 | 原有 BIN/HEX/H7 能力门槛已有明确升级提示；SWD 状态清单补充 BIN/HEX |
| 供电遥测 / 探针诊断 / live presence | 原有缺 API 的升级说明保留；V2 缺功能不承诺升级可得；电流硬件、Vref 自动跟随及未知写结果不扩大支持范围 |

HPM OTP 写入响应丢失/不完整、未知目标/安全白名单、调试器占用、采集中改频率、
USB 身份/链路失败及 S3 传输限制均不被笼统改成“升级即可解决”。

## 实物方法与结果

Windows PowerShell 7 / Python 3.14，普通 V4、STM32F103RC、SWD 10 MHz。
用户目标工程 AXF 的 Flash 段共 117760 字节与实物逐字节一致；AXF SHA-256：
`3a63715eaad61949bebc90fdf03175b08f80e008912c9cc6127f11f337694f77`。
复制符号至非系统盘验证工作区，未修改用户工程配置、目标映像或 VCC。

四个正弦波 float 与一个不参与控制的 uint32，共 5 个通道、两个读取区域，请求间隔
1 µs；每轮写入 100–109，再恢复原值 0。原始二进制流检查实际值跃迁、时间戳、
序号及完整性。ACK 只证明写请求已应答，不冒充读回校验；采样实际出现相应值，停止后
另行读回确认恢复。命令口始终通过共享后台访问。

| 固件 / 上位机 | 原始组数 | 组/秒 | 采样间隔 P95 / 最大 ms | 写 ACK 中位 / 最大 ms |
|---|---:|---:|---:|---:|
| V4.7.3 / 修改前 | 146588 | 15796.95 | 0.084 / 0.195 | 15.534 / 19.042 |
| V4.7.4 / 修改前 | 147010 | 15867.93 | 0.084 / 0.208 | 14.846 / 17.256 |
| V4.7.4 / 修改后 | 146842 | 15867.54 | 0.084 / 0.192 | 15.726 / 19.283 |
| V4.7.4 / 修改后，RTT 0/1/2 并行 | 127773 | 13812.36 | 0.160 / 1.562 | 15.777 / 18.008 |

各轮均为 `cdc-mux`、全程 running，10 次写入及恢复值在原始数据中出现；
无时间倒退、序号断裂、连续性缺口标记、读取错误或队列丢弃。RTT 并行保持 streaming，
传输 event gap 和各通道丢字节计数均为 0。该轮未做 RTT 字节流内容比对或独立吞吐 A/B。
写命令仍占用共享调试总线，不能承诺零额外采样间隔；本次短测不证明所有负载无退化。
基线中的普通读取 P95、20 µs 最大采样间隔、40 µs 零漏采目标仍未达成。

## Web、软件与边界验证

- 生产 Web 真实浏览器在实物采集中点击写入 123，显示“已写入: 123”和运行中约
  15.9 kHz；后台记录同一 `cdc-mux` 写事件，观察到 1754313 组、零读错，最终恢复 0。
  GUI 辅助脚本结束时误用采集中不允许的 `watch` 查询得到 409；finally 已完成恢复及停止，
  拒绝没有触发写重放。取值已由 GUI、采样和写事件确认。
- 另一无硬件夹具提供缺能力的 V4 文本状态，验证中文/英文清单、固件页面跳转和返回后
  再次跳转；未触发下载或升级。真实 V4.7.4 状态清单为空，不产生无根据的升级横幅。
- 后端广泛关联回归 1711 项通过；一个新增复位入口断言误将 Web 任务准入当成直接复位，
  修正后相关 271 项通过；最终 SuperWatch/能力/复位专项亦通过。Skill 分发边界 69 项通过。
  数量有重叠，不累加。覆盖缺能力无写/停流、暂停状态、HPM RAM、未知结果、真实 HTTP/
  RuntimeClient/FastMCP 一致性和状态查询无设备 I/O。
- GUI 全量 1222 项通过，TypeScript 与生产构建通过，受跟踪 `gui/dist` 同步。
  未重新生成或覆盖 Windows/macOS 安装包；既有候选包不包含本次新增提示。
- HPM、V2、V3 的本轮实物能力矩阵未重测，使用协议和软件夹具验证，不以 V4 测试代替。
  未做完整 CMSIS-DAP 调试器共存或所有性能基线 A/B。
