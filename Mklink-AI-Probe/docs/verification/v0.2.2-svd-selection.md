# SVD selection after changing chip (0.2.2 development)

Directly typing a different chip left the SVD select empty even when the target
API returned a matching installed SVD. The component filtered by a chosen model
that was only set by clicking/confirming an autocomplete suggestion.

The SVD select now exposes current search results without requiring that extra
step. Choosing an SVD confirms its model. Options include model, filename and
Pack version; editing clears stale candidates immediately and late responses
cannot replace newer results. Empty searches have no SVD options, unmatched
models show an installed-Pack hint, and the existing catalog is explicitly
labelled as currently loaded until the user loads another one.

Validation:
- PeripheralWatchPanel: 3 tests passed (existing GPIO interaction; direct chip
  switch, multiple Packs and no match; out-of-order search responses).
- TypeScript check and production GUI build passed.
- Real Chrome against the local backend reproduced the original failure:
  STM32F103C8 target API returned STM32F103xx.svd but the select had only a
  placeholder. After rebuilding, direct typing exposed that option and selection
  succeeded. Switching again to STM32F103RE and loading produced 4876 read-only
  catalog items. Original variable sampling was resumed.
- APM32F072VB Pack is not installed in this environment; this is not a claim of
  APM hardware validation. No new peripheral was sampled during this UI test.

No probe firmware change or release is included.
