# STM32F103 桌面、Web 与 UART5 验收

2026-11-25 在 Windows 上使用 HPMLink V4.7.5 和用户的 STM32F103 测试板。工程为 `E:/PHDZ/PROJECT/liu/STM32F103_test/STM32F103RC`。命令口为 COM62，TTL 串口为 COM61。PC12 为目标 UART5_TX，PD2 为 UART5_RX。

## 镜像、时钟与接线

板上最初的 117,760 字节与工程归档的 AXF 匹配。当前 build 中的 AXF 与归档向量表相同，完整程序不同。第一次在线烧录从 `0x08005000` 写入工程 BIN，独立回读核对了整段应用、前方 20 KiB Bootloader 及末扇区剩余 1 KiB。

UART 两端初设 115200 时出现乱码。目标配置 76800、主机保持 115200 时，板端计数、哈希和串口回执同时正确，系统节拍也约快 50%。将这个测试工程的 HSE 改为 12 MHz、PLL 改为六倍，并处理 Bootloader 已启用其他 PLL 倍频的入口条件。Keil 编译结果为 0 个错误，4 个警告来自 RT-Thread C 库的非空参数检查。

修正后的 BIN 为 118,272 字节，SHA-256 为 `2f36aa541f92a136281b8d736c04c36097b2dae569bc434fb1ad52de17f12f3c`。实板在线烧录、复位、逐字节回读通过。Bootloader SHA-256 仍为 `d7f5ba1130c7f5a3f624285350a2ea347e70d0e10c7220d4ae0fc73e0835b29c`。三秒采样测得 1,000.07 tick/s，目标报告 72 MHz。两端设为 115200 后，目标正确接收含零及高位字节的测试数据，主机读到对应哈希回执和连续的 UART5 序号。

## 采集与文件

最初镜像实测 SuperWatch 四路记录 35,573 组，Excel 行数正确，首、中、末样本与源日志一致。GUI 采集期间独立 CLI 订阅 RTT 15 秒，通道 0 读取 46 字节，通道 1 读取 8,325 字节并解析出 225 个点，两个通道丢失字节均为零。SystemView 日志记录 635,372 个事件、9 个任务，解析、目标和主机丢弃计数均为零。另取到 500 个 VOFA 点、SVD GPIO 寄存器值，验证了脱机预览。

工程采集文件位于用户工程的 `.mklink/logs`。本轮测试结果与构建日志位于 `F:/MKLink-Build/reports/v051-f103-file-buttons-20261125`。RS485 收发器未接线，TTL 上的 Modbus 验证只覆盖该串口和协议。
