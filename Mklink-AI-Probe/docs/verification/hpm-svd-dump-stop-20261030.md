## legacy/B1 dump 修复

客户 STM32F411 4 KiB 报告区分了两个独立问题：启动的 50 字节是命令回显，
而停止命令确实收到 `Error: DAP busy`。随后身份 token 成功不能证明采集停止。
后续内存读也收到 busy，旧解析却转为空字节。报告中的原始二进制附件尚未提供，
本次回归使用报告中的控制文本及合成的有效 OLD/B1 帧，不宣称已重放原始抓包。

- 仅剥离本次精确启动命令回显，单列 `startup_control_bytes`；中途回显、
  异常字节及 CRC/帧损坏继续计数，性能验收的完整性门槛保持有效。
- 停止期间保持原始字节接收，按外层长度与 CRC 隔离 OLD/B1/ACK 帧，
  保留上次采样解析未消费的半帧，不在 RAM 负载内匹配控制标记。
- 进入流前缓存固件能力。声明 `DUMP_STOP=1` 时必须收到独立完整
  `DUMP_STOPPED` 行与提示符，随后一次身份同步及安静尾部检查才进入 READY。
  等待上限 2 秒，覆盖固件 500 ms 停止与 250 ms ACK 排队预算。
- 兼容无标记的旧固件，但要求无错误、命令同步成功且停止响应后无旧帧。
  拒绝、超时、坏帧或持续输出均保持 ERROR；只发一次停止，不重放采集。
- busy、SBA 和明确的读取错误保留原始原因；即使先收到部分十六进制行也不返回成功。
  Skill 同步说明恢复边界，不以忽略统计、循环停止、补读或改时钟掩盖故障。

相关 Python 回归最终 **791 项通过**，覆盖逐字节分包、半帧、RAM 内伪标记、
拒绝/超时/缺确认、旧固件、延迟提示符、持续帧、部分读错误及 MUX/RTT/Watch 回归。
固件改动由用户指定的固件会话负责；本会话未修改或发布固件。
